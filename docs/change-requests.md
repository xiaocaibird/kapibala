## CR-001 群名称

**用户要求：**创建群时可选填写名称；已有群能够改名。名称属于本系统的本地 metadata，不向 gateway 同步。群列表、群详情优先显示名称；无名称的旧群继续显示 `gatewayGroupId`。

**影响：**群表增量迁移、共享 Group 类型、创建任务持久参数、创建及修改接口、列表和详情。保留本地群ID与网关群ID的原用途；显示名称不能成为远端请求的群标识。

**实现建议，非用户已确认限制：**新增可空 `name`；非空名称先 trim，再按 1–80 字符校验。创建请求可省略名称，旧数据保持 null。管理员修改名称沿用现有写权限；省略字段不覆盖既有值。当前方案不允许清空已填写的名称；“不可清空”和最大80字符均为技术提案，不是用户已确认的业务限制。

**验收：**见下方 N01–N04。已实现待验收，用户未确认本项；不把之前成功建群的反馈当作名称功能已通过。

## CR-002 群创建时间展示

**用户要求：**群列表展示真实创建时间，并带本地日期。

**影响与数据来源：**使用数据库已有的 `groups.created_at`，保留旧值。它表示本系统持久群记录的创建时刻；不使用页面加载时间、改名时间或任务更新时间代替，也不声称外部协议提供了更精确的远端创建时刻。

**实现建议：**Group 增加 `createdAt: string`，以带时区信息的 ISO 时间传输；浏览器转换成本地日期和时间展示。接口格式属于技术契约；排序方向另见 CR-003。

**验收：**见下方 T01–T03。已实现待验收；实现与开发验证见下方记录。

## CR-003 群创建时间排序

**用户要求与未定项：**用户提到创建时间排序，但关于升序或降序的话语未完整，尚不能判断用户最终偏好。

**现状与实施建议：**基线 `542d2a2` 的群列表查询已经使用 `created_at DESC,id`，即较新创建的群在前，时间相同按ID稳定排序。当前建议沿用，作为已有实现登记；排序方向待用户确认，不阻塞 CR-001、CR-002、CR-005。不得将“DESC,id”写成用户已作出的决定。

**验收：**S01 检查实际顺序与稳定性，S02 单独记录用户对方向的确认；接口同时间稳定排序及本轮浏览器不同时间倒序检查通过；用户方向仍待确认。

## CR-005 群简介

**用户要求：**创建群时可选填写简介；管理员可以编辑已有群的简介；群详情展示简介。允许清空，旧群无简介时不编造内容。该字段随本批群 metadata 在本地保存，不扩展 gateway 同步协议。

**影响：**群表新增可空字段，创建任务、共享类型与接口携带简介，创建表单、管理员编辑及详情展示支持该字段。

**实现建议，非用户已确认限制：**内容先 trim，最大500字符；空内容归一为 null。PATCH 未提供简介时保持原值，明确清空时才清除；名称与简介局部更新互不覆盖。当前 PATCH 提供 `description` 时只接受字符串：空串或 trim 后为空的字符串清空简介，显式传 `null` 返回400；响应/存储中的空值仍为 null。最大500字符及该输入表示方式是当前实施建议。

**验收：**见下方 I01–I04。已实现待验收；实现与开发验证见下方记录。

## 数据保留与更新边界

用户明确关心合并变更时是否产生脏数据。本批方案采用增量 nullable 迁移：已有群的名称/简介为空，既有 `created_at` 及业务数据保留；旧创建请求不传新字段仍兼容；PATCH 只修改显式提供的字段。独立旧库迁移、接口局部更新与真实行锁并发断言已通过；当前演示的备份、升级及保留核对另记实际运行结果。

不同字段的局部更新各自保留未提供的值；多个管理员并发修改同一字段时，当前方案按最后写入生效，不新增 CAS 或版本冲突提示。该边界不表示并发修改会自动合并。

已保存到服务端的记录与浏览器中尚未提交的输入分开处理。保留持久数据不能保证未提交表单跨页面刷新或服务更新仍在。必要的后端重启前，由协调者报告具体影响，在独立环境验证后安排更新；不得用本台账承诺尚未执行的备份、迁移或重启结果。
