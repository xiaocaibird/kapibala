# 历史读取、共享推送资源与后台调度观测

本轮基线为 `7339f7e`，实施分支为 `agent/core-resource-observability`。产品及专项测试提交为 `47b0dae`，控制帧与事件帧共用有界串行发送的补修为 `6f751c9`。范围是第五项历史增长与共享资源的局部治理，以及第六项的最小运行观测；不重写时间线、事件接收或业务调度架构。

## 已实施的范围

| 问题 | 当前处理 | 保留的行为与边界 |
| --- | --- | --- |
| WebSocket 慢客户端可能不断积压待发送帧 | 事件逐帧等待发送回调；发送前检查缓冲水位；单帧发送回调长时间未完成则关闭，关闭握手不结束再终止连接 | 从客户端真正收到的序号重连回放。发送回调只说明交给传输层，不代表用户已收到。关闭不删除持久事件 |
| 快速切页或异常客户端同时提交大量提醒起点请求 | 单连接串行分批读取水位，并保留每个已接纳请求的关联 ID；待处理集合最多 128 个，溢出关闭连接 | 不把控制帧当成持久事件，不推进事件游标；不丢弃已接纳请求的正常响应，只在超限时明确断开 |
| 每条时间线续页都将整份冻结快照取回 Node | PostgreSQL 对现有 JSONB 快照取指定分页片段，同时返回总条数 | 不改游标格式、快照 ID、冻结成员集合、顺序和内容；不删除快照、不使旧游标失效 |
| 健康检查无法区分后台模块近期失败、阻塞或持续推进 | 增加管理员只读后台诊断，包含模块名称、恢复状态、tick 次数、最近开始/完成/成功/失败时间和当前运行时长 | 原健康接口保持存活及 schema 信息。诊断是当前进程的调度循环状态，不代表子任务完成、网关在线、数据库正常或集群全局健康 |

实现位置：

- `apps/server/src/core/socket-sender.ts`：传输缓冲水位、逐帧完成、超时关闭和终止兜底。
- `apps/server/src/core/realtime.ts`：事件回放接入发送保护、提醒起点批处理、关闭后停止轮询。
- `apps/server/src/modules/gateway/index.ts`：冻结快照续页 SQL 切片及网关模块名称。
- `apps/server/src/core/module-progress.ts`、`apps/server/src/app.ts`：后台 tick 进度和受限诊断。

## 资源边界的实际含义

推送默认缓冲水位为 **1 MiB**，发送回调等待默认 **5 秒**，关闭握手兜底为 **1 秒**。这些是内部实现参数，不是远端网关或 Agent 的新能力。一次大于水位的单帧，在连接已排空时允许发送，避免仅因一条合法历史事件较大而永久无法重连恢复；事件与控制响应使用同一个有界串行发送器，最多一条发送中、两条等待。不能无界追加，控制响应也不会因为大帧暂占缓冲而提前打断它。

因此这里约束的是逐连接待发积压，不能解释成整个进程内存严格不超过 1 MiB：单条事件本身、一次最多 500 条的数据库回放结果、连接数量、TCP 缓冲及其他业务内存仍需计入。消息内容和已提交事件均未被截断或删除。

关闭后，未发送成功的事件不推进当前服务器连接的游标；即使传输层已经接受而客户端尚未看到，客户端重连也只带自己最后实际收到的序号。服务器从持久事件表重新查询，不使用断开连接的尝试发送位置作为接收确认。

JSONB 切片只减少数据库到 Node 的回传量和 Node 对整份快照的反序列化开销。PostgreSQL 仍可能读取、解压和访问整份 JSONB/TOAST 数据；本轮没有证明数据库查询总体复杂度降低。首屏仍生成完整冻结快照，反复打开首屏也仍会新增快照。

## 诊断权限与含义

`GET /api/diagnostics/background` 需要有效的管理员会话。匿名访问返回 401，只读用户返回 403。响应仅含进程级调度状态和时间/计数，不返回令牌、连接信息、群或消息内容、异常正文和堆栈。

`background: false` 显示 `disabled`；尚未运行显示 `not_started`；已有 tick 失败显示 `failed`，正在运行则显示 `running` 并给出当前持续时长。后续成功会清除连续失败计数，但保留最近失败时间。模块 tick 日志增加模块名字，便于关联已有错误日志。没有设置一个任意时长就判定业务故障的全局阈值。

网关 tick 可能只是启动异步业务任务，因此“tick 成功”只证明调度循环返回；不能用它证明账号发送、建群、模型调用或事件入库完成。该接口本身也依赖认证与数据库连接，不能承担数据库故障时完全独立的探活职责。`/api/health` 的返回格式没有修改。

## 验证结果与证据

[专项与既有消费者合跑](evidence/core-resource-observability-targeted.tap)：**59 项通过、0 失败、0 跳过**。其中新增专项 11 项，合并既有网关及实时提醒事件测试。测试使用专用 PostgreSQL 服务，每个数据库场景独立创建并回收 UUID 数据库，随机端口和测试自己的 WebSocket 连接；没有使用演示库、用户浏览器或 QA 验收套件。

| 场景 | 实际检查 |
| --- | --- |
| 单条大帧后继续写入、发送回调永不返回 | 后续发送被拒绝；关闭后没有新帧；对端不结束握手则终止；正常关闭会取消终止定时器 |
| 单帧大于水位但客户端正常消费 | 大帧及后续帧都能完成，不因大小单独陷入永久重连 |
| 大帧与控制回复同时发送、待发送队列超限 | 控制回复等待大帧完成，没有因控制回复而提前中断；第四条同时提交的待发送帧触发关闭，所有等待者结束，没有发送后续帧 |
| 真实 TCP 读端暂停 | 暂停客户端被清理；另一健康连接继续收到 80 条事件；使用实际已收序号重连后身份、顺序、内容序号无遗漏和重复；所有连接关闭后没有继续事件轮询 |
| 提醒起点突发 | 人工挂起一次水位读取，再连续提交 100 条控制请求；同时在途水位查询最多一个，仅需两次水位读取且 101 个关联 ID 均有响应；持久事件仍回放 |
| 提醒起点超过待处理容量 | 超限关闭，挂起的查询释放后不再继续其他查询或发送响应，没有无界数据库工作 |
| 123 条消息的冻结快照续页 | 原快照为 **1,252,279 字节**；每页 9 条时数据库实际回传最多 **91,661 字节**。改变原消息内容与时间、追加新消息、切换页大小后，全部续页仍与初始快照严格一致；跨群游标和非法游标拒绝，超大偏移正常返回空页 |
| 后台诊断 | 验证匿名/只读/管理员权限；禁用状态不假装运行；注入一次失败及一次等待，再恢复，失败、进行中、完成状态可区分；错误正文不出现在响应中；原健康接口格式不变 |

慢 TCP 用例为确定性验证使用了更短的内部发送等待（1 秒）和关闭兜底（50 毫秒），其结果证明关闭、隔离和回放机制，不是生产环境在任意负载下的延迟承诺。提醒突发用例的挂起发生在测试注入的查询入口，不是 PostgreSQL 锁竞争基准。容量数字来自本轮场景，不表示系统的最大容量。

## 本轮不做、保留风险与建议

| 范围 | 当前结论 | 后续建议与前提 |
| --- | --- | --- |
| 快照生命周期、全量历史增长 | 没有删除、TTL 或自动失效策略；存储仍可能持续增长 | 先明确允许保留时长、仍有效游标的生命周期和可恢复语义，再设计压缩、复用或回收。不能为节省空间擅自破坏已有游标 |
| 首屏全量快照与长期大历史 | 仍有整份读取和序列化成本，未声称支持任意历史规模 | 明确实际历史量与延迟/资源目标后，评估不可变版本索引或其他增量快照方案，保持冻结分页语义 |
| 共享数据库连接与客户端总量 | 现有执行容量机制继续有效；未独立拆池或新增全局连接限额 | 先测量并发连接、调度/事件/读取的连接占用，再判断限流、专用连接或池拆分。单个慢客户端的局部加固不等于全局资源隔离 |
| 事件回放吞吐和全局诊断 | 保留原事件表和回放扫描方式；后台诊断为当前进程级数据 | 达到已明确的业务规模后再评估回放批量/增量优化和跨进程聚合，避免以观察接口的存在代替端到端证据 |

这些未实施项有明确保留结论，不记为已实现或原始全部保证已满足。没有新增外部服务能力，没有迁移、演示环境切换或主分支合并。
