# 账号远端操作与本地提交：恢复方案影响评估

日期：2026-10-01。对应 V-ACC-01。本次为源码与既有实证复核，没有新增账号实验或修改账号实现；不是已批准实施方案。

## 当前事实

`Accounts.connect/transition` 在数据库账号行锁内调用远端，远端成功后写入平台身份、账号状态和关联事务事件。本地事务失败会释放锁；外部效果不会随本地回滚撤销。`expectedFrom` 只比较状态，不是单调操作版本。当前表没有独立的账号操作账本或防止旧恢复覆盖新操作的持久代次。既有真实HTTP/PG故障证据见[账号边界实验](core-gateway-repair.md#v-acc01实测不一致与可观测缓解560ad65)。

新增诊断只覆盖当前进程已经观察到成功、但本地保存未确认的情况；它不提供自动恢复。原协议明确同账号connect返回稳定平台身份，但没有明确跨崩溃的操作去重、远端处理顺序或账号当前状态查询。不能把稳定身份等同于完整操作幂等，也不能直接认定所有修复均需新增外部协议。

## 可选路径与边界

| 路径 | 能解决的范围 | 不能解决的窗口及影响 |
|---|---|---|
| 原事务内保存点及有限本地重试 | 同一连接、外层账号锁仍持有、已知200且可恢复的语句失败 | 连接失效、未知COMMIT、进程终止不在覆盖内；永久触发器错误重试仍失败。不能把局部成功写成V-ACC-01闭合 |
| 请求前持久操作意图＋单调账号代次＋恢复执行器 | 让恢复知道目标状态、操作顺序和是否仍为当前意图；防止旧结果无条件覆盖新操作 | 需要迁移、账号操作准入与恢复工作流，需保护终态、CAS和已排队业务。不增加远端信息时，未知请求是否仍会迟到生效仍待解决 |
| 原协议内按目标状态重新执行 | 已明确旧调用完成、无更新操作且远端重复操作语义可靠时，可能重新收敛connect/disconnect | 必须先证明重复调用及迟到请求的顺序保证；仅在本地加锁或设置版本不能阻止更早的远端请求晚于新请求生效 |
| 外部提供操作结果/版本或可靠状态核对 | 当内部方案不足时，为未知结果和旧请求迟到提供依据 | 属外部契约改动，须单独评审；不能先在模拟器添加能力再宣称原协议已满足 |

## 建议与需要的决定

当前不提交一个只能覆盖语句失败、却会被误认为解决全部恢复的重试补丁。建议先评审“持久意图＋账号代次＋恢复准入”这一有限内部方案，并将已观察200与响应未知分成两个分支。若原协议无法支持响应未知分支，必须单独报告所缺判据，不默认增加协议、不接受偏差。

结构影响包括新增持久操作记录、所有账号变更入口与终态事件的代次协作、重启扫描、过期结果处理和CAS返回语义。它超过单点保存重试，按D023留待评审；当前公开API和状态枚举不变。

实施前应给出以下反例的预期：远端200后本地语句失败；COMMIT应答丢失；保存前终止；旧操作失败后新操作成功；状态A→B→A；远端旧请求晚于新请求完成；远端终态事件与恢复并发。自测必须对照本地状态、远端实际状态和操作次数，不能只看告警出现。
