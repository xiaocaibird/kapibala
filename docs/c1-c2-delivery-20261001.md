## QA 接入变化

QA 仍独立维护用例、断言、目标配置和结果；接入核对、正式业务验收、上线评估分阶段处理。本交付提供产品事实，不代填 QA 的权限、定位确认或 PASS。

1. 在独立 SUT 工作树冻结上述候选，使用锁文件准备依赖（`npm ci`）。普通服务仍可用 `node --import tsx apps/server/src/main.ts`；已有组合观测入口 `node --import tsx scripts/qa-observation-server.ts` 及三个控制器契约保留。
2. `node --import tsx scripts/migrate.ts` 增加 `009_media_files.sql`，当前目标 schema 为 9。历史库测试须保留原归档和真实迁移链；不要修改旧迁移或把旧 schema 断言机械放宽。
3. C1 给每个独立数据库配置对应的 QA 自有持久绝对目录 `MEDIA_DIR`。同库重启保持目录不变；同库多实例共享同一物理目录。测试结束按所有权清理，不能复用演示媒体目录。网关、数据库、端口仍使用 QA 独立资源。
4. C1 改动包括下载/清理 worker、消息可选 `localFilePath`、时间线返回当前路径、Agent 活动引用保护。`localFilePath` 是服务端文件路径，不是浏览器下载 URL；文件内容不因此自动进入模型。消息文本和正常发送接口保持原契约。详细默认值及失败路径见[C1 说明](c1-media-files.md)。
5. C2 是独立 HTTP 服务，用 `node --import tsx apps/gemini-agent/src/main.ts` 启动；使用独占私有 `GEMINI_SESSION_DIR`，从 ready 输出取得地址后显式配置后端 `AGENT_URL`。默认模型为 `gemini-3.1-flash-lite`。已有隔离启动继续用模拟 Agent，不因本地存在 Key 自动调用 Gemini。
6. C2 保留 `/agent/turn`、`/agent/audit`，工具执行、审计执行顺序、权限与预算仍由主后端负责。QA 可先做协议和离线影响核对；本交接不追加真实模型费用，也不复制用户 `.env`，真实调用需使用明确管理的凭据与范围。
