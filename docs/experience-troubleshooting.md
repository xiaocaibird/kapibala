# 体验注意事项与故障处理

本文集中列出体验过程中需要特别关注的入口差异、已知限制和处理方式。从[根目录 README](../README.md)进入即可查阅。目标是帮助定位问题并继续可用的体验路径；涉及未知执行结果的原任务，不能保证恢复或自动完成。

## 按现象快速查找

| 遇到的情况 | 先做什么 | 处理入口与边界 |
| --- | --- | --- |
| 初始或样例环境打不开，或者样例还没出现 | 等待 `isolated-ready`，使用其中的 `urls.web`，不要沿用固定端口或旧标签页地址 | [启动与样例](../README.md#快速体验初始环境样例环境与重置)；Docker 须已运行且当前用户可访问。启动失败先查看终端错误，不把中间进度当成功 |
| 想清空操作记录，或重新生成样例 | 在该隔离环境的启动终端 Ctrl-C，等 `isolated-cleaned`，再启动目标模式 | [两种基准的重置](../README.md#重置为空环境或样例环境)。旧数据会删除；只刷新浏览器不是重置 |
| 隔离环境遭强制终止，清理没有完成 | 使用本次启动日志中的 manifest 执行精确清理；Docker 不可用时先恢复同一 daemon | [中断清理](../README.md#中断后的精确清理与入口自检)。不使用其他环境的 manifest，不执行全局清理 |
| 填了 Gemini Key，仍看到模拟 Agent | 确认使用的是 Gemini 常规启动流程，并将后端连接到它的实际地址 | [真实模型启动](../README.md#可选-c2真实-gemini-agent)。隔离和样例入口固定使用模拟 Agent，不能靠修改 `.env` 原地切换 |
| Gemini 已启动，但群里没有自动回复 | 确认服务账号已连接、群已建好且开启自动应答，再注入外部成员消息 | 见下方“触发一次真实模型体验”。服务 ready 或健康检查成功不代表已调用模型；平台账号自行发消息不等于外部触发 |
| Gemini 异常退出后无法再次启动，提示目录锁 | 停止相关实例，确认会话目录归属并备份，再按专门步骤处理遗留锁 | **见下方“Gemini 崩溃后的人工恢复”**。不能直接删整个目录，也不能假定原模型任务会恢复 |
| Gemini 请求失败、限流或超时 | 查看启动终端和运行详情；核对 Key、模型可用性、额度、网络和服务地址 | [错误与时限说明](c2-gemini-agent.md#会话读写和失败边界)。不要连续重发来试运气；超时或取消不证明供应方没有执行或计费 |
| 运行暂停、结果未知或审计阻塞 | 先读该运行的原因和工具结果，保留原记录 | 未知移除或模型结果可能保持安全暂停；不要修改状态、删除会话或重复操作来冒充恢复。见[第二轮处置](second-round-disposition-20261002.md#八项处置表) |
| 提醒不明显，或切换页面后提示消失 | 回到实际目标群/运行核对数据；必要时刷新该页面重新查询 | 跨实体提醒仍有未完成验证的范围，提示图标不能单独作为数据已读或业务成功的证据；见[处置第 6 项](second-round-disposition-20261002.md#八项处置表) |

## Gemini 崩溃后的人工恢复：体验前特别留意

**已知限制：强制终止或硬崩溃可能留下会话目录锁，导致服务无法重新启动。当前没有自动接管。** 正常退出会尝试释放锁，日常结束请优先在启动终端使用 Ctrl-C。

遇到此情况，按[独立模型服务遗留锁的人工恢复](c2-manual-recovery.md)逐步执行：停止所有访问该目录的实例和自动拉起机制 → 确认准确目录与归属、锁无人使用 → 完整备份 → 仅移走已确认遗留的锁 → 用原配置单实例启动并检查健康状态。

- `SESSION_DIRECTORY_LOCKED` 也可能来自其他文件系统错误，不是看到这个提示就能删锁。
- 不要删除整个会话目录、改写会话 JSON，或把未决状态改成完成；也不要只凭 PID 不存在就判断锁可移除。
- 恢复服务对目录的访问，**不等于恢复原未决模型轮次**。原轮次可能继续返回 `TURN_OUTCOME_UNCERTAIN`；不要通过换运行编号或重发同一逻辑请求绕过保护。
- 这项人工恢复限制已被接受；恢复说明基于源码核对，尚未进行实际人工恢复演练，不把说明本身当成恢复测试通过。

如果只是继续查看界面和样例，可以另按 README 启动独立模拟样例环境；它不使用原 Gemini 会话目录，也不代表原任务已恢复。保留原环境与记录，两个环境的数据不互通。

## 触发一次真实模型体验

先按 README 完成 Gemini 的双终端启动，登录后台连接服务账号、创建一个测试群并开启自动应答。该流程仍使用模拟消息网关，需要手动产生一条外部入站消息；真实调用会消耗模型额度。

在另一个终端查看模拟网关中的群 ID：

```sh
curl --fail --silent --show-error http://127.0.0.1:3101/__control \
  | node --input-type=module -e 'let s=""; for await (const c of process.stdin) s+=c; console.log(Object.keys(JSON.parse(s).groups).join("\n"));'
```

全新常规环境只创建了一个群时，输出就是该群的网关 ID。已有多个群时，先核对目标对应关系再继续，不能随意取第一个。**不要直接使用浏览器群详情 URL 中的平台内部 ID。** 将下面的占位符替换为已确认的网关 ID：

```sh
curl --fail --silent --show-error http://127.0.0.1:3101/__control/message \
  -H 'Content-Type: application/json' \
  -d '{"groupId":"替换为网关群ID","senderPlatformUserId":"demo-external-user","text":"请在群里回复一句你好，然后结束。"}'
```

随后在后台查看 Agent 运行详情和消息记录。上述接口成功仅表示已注入事件，不等于模型调用或发送已经成功；以运行详情中的实际结果为准。若审计阻塞或模型失败，保留原因，不反复注入相同消息。控制接口仅用于本地模拟输入，更多说明见[模拟服务](simulator.md)。

## 停止、重置与数据保留不要混用

- **隔离初始/样例环境：** 正常停止并清理后，重新运行对应入口，得到新的基准环境；地址和登录会话也会变化。
- **Gemini 常规环境：** 停止服务和 `docker compose stop postgres` 会保留数据库、模拟器状态及模型会话。再次启动是继续使用原数据，不是恢复初始状态。
- 当前没有 Gemini 常规环境的一键样例生成或完整重置入口。想返回可重建的初始/样例体验，正常停止常规服务后使用隔离入口即可；这不会清除原常规数据，也不会把它复制到新环境。
- 不要通过只删除数据库卷或只删除会话目录来声称完成整套重置，各类持久数据之间存在关联。旧数据库升级另见[升级边界](../README.md#数据库升级边界)。

## 结果与证据边界

本页提供体验中的操作指引，不新增产品能力、不改写验收结果。初始/样例正常启动与重建已有开发验证；Gemini 最终版本的有限真实 turn/audit 复验通过，不代表所有业务流程或故障恢复均通过。微小五秒超限已按本次测量接受；未知结果恢复、目录锁及实际写入失败证据等仍按原处置保留。详细结果以[两轮验收入口](../README.md#关键文档)和[第三轮规划](third-round-plan-20261002.md)为准。
