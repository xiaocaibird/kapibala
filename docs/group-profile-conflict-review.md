# 群资料字段并发保护

## 授权与基线

本批只承接用户明确批准的 PI-03 第三项：群名称、简介的同字段并发冲突保护。群创建和资料编辑的重复提交、忙碌关闭、未保存关闭保护已经由 CR-010 独立交付；序列表单及 PI-03 其他建议没有随本次获准。PI-04–23 暂缓，完成本项后优先验收原始核心能力及处理验收发现的问题。批准实施不等于用户验收通过。

原始 2.3 要求保留 `PATCH /api/groups/:id` 的开关字段、响应和权限，并允许额外 API 设计。群名称和简介来自既有补充需求；本次在同一接口增加可选比较条件，保留开关原行为、创建流程、存量字段和迁移版本，不重构核心业务。原始需求文件保持字节不变。

## 比较条件与事务

当前控制台资料表单为本次实际修改的资料字段发送原值，例如：

```json
{
  "name": "新名称",
  "expected": { "name": "打开表单时的名称" }
}
```

`expected` 一旦提供，必须非空，且严格对应本次写入的 `name`、`description` 字段，不允许漏项、额外项或未知字段。其值允许字符串和 `null`，原值不裁剪、不归一化。待写名称仍需 trim 后 1–80 个 UTF-16 单元，已填名称不可清空；简介 trim 后最多 500 个单元，空字符串清空为 `null`，待写值显式 JSON `null` 仍不接受。

后端在现有事务内锁定群行，UPDATE 的 WHERE 使用 `IS NOT DISTINCT FROM` 原子比较本次字段。一个条件不符就返回 `409 GROUP_PROFILE_CONFLICT`，业务字段包含比较时的 `current: {name, description}` 和 `conflictingFields`。整次请求不写任何资料或开关，不发变更事件，也不取消 Agent 运行。不同字段的局部编辑互不阻挡其原值条件，允许依次成功。

这是一种当前值比较，不追踪 A→B→A 的历史。错误里的服务器值是冲突检查时快照，用户重新确认时仍需再次比较；快照不承诺一直是最新值。

## 草稿与明确重新确认

编辑基线固定在打开表单时，不随轮询或实时推送抬高。发生冲突后保留本次已编辑字段的原始输入，展示服务器快照与待保存内容；未编辑字段跟随服务器快照，避免重新确认时误写回旧内容。界面保持打开且可继续修改，不自动重试、不提供无条件强制覆盖。

用户明确重新确认后，带新比较条件再次提交。如果期间又有同字段更新，仍返回冲突；如果待保存内容已经和服务器一致，可无写入完成。所有异步结果受表单生命周期保护，已经卸载的表单不能更新草稿、刷新或关闭后来打开的表单。关闭页面不等于取消服务端已经受理的请求。

## 兼容边界

不带 `expected` 的旧请求继续保留原有最后写入语义；本项保护覆盖携带比较条件的请求及升级后的资料编辑界面，不能宣称所有旧客户端已受保护。旧调用方仍可能覆盖其他编辑，应按此契约升级后才获得保护。无需迁移或重置数据库，群开关单独 PATCH 不强制携带资料条件。
