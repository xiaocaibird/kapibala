# 网关、账号与消息可靠性

## 模块职责

`gateway/index.ts` 注册 REST 并独立调度账号发送、群任务、限流恢复及事件重试。`accounts.ts` 负责账号操作；`state.ts` 维护跨模块原子状态后果；`messages.ts` 是所有来源共用的发送与成员移除适配；`jobs.ts` 执行持久建群/退群步骤；`events.ts` 接收、校验、重放和去重网关事件。长远端请求只占所属后台任务，不阻塞全局 tick。

## 状态与并发

账号手动变更使用行锁及 expectedFrom 校验。终态、群成员清理、queued 取消、对应序列步骤 skipped 和持久事件在同一事务提交。群不可写同事务停止序列并请求 Agent 在当前步后取消。跨实例使用 PostgreSQL 会话级 advisory lock 排他执行账号发送和单个群任务；连接中断释放锁，但不会据此认定远端副作用没有发生。

## 发送、超时与恢复

发送先写 outbox，远端调用前保存 dispatch intent。只有已知 NETWORK_TIMEOUT 响应才开启 2 秒否定确认窗口；明确超过此窗口仍 404 时使用同一 clientMsgId 最多重发一次。查询不可用维持 unknown；已落地的查询或事件更新为 sent。没有已知 504 的进程中断/传输超时只查询，不自动重发。503 作为明确不可用响应退回待处理状态，后退 500ms 重试。

协议没有全局请求去重，不能证明任意崩溃下全局恰好一次。创建群响应丢失也没有结果查询接口；此类任务保留 running 并提供 recoveryNote 及 inconsistency，等待核验。kick 返回 504 后查询成员；目标仍在时无法区分未移除与移除后重新入群，不盲目重试。未确认结果不伪装成成功或确定失败。

## 事件与分页

SSE 从 since=0 重放全部历史，在业务事务内依 event_id 去重。失败事件不被标记成功，可在当前进程重试，重启后从网关完整历史恢复；inconsistency 在数据库可写后持久发布。自己的回流通过 by-client-id 关联到稳定 outbox id。成员事件查询网关当前列表，避免历史乱序覆盖当前状态。时间线首次请求持久化完整快照；后续 cursor 使用快照及偏移，快照内容和顺序固定。新消息及状态变化由实时视图按稳定 id 合并。该方案优先演示规模正确性，历史重放及快照存储成本随历史增长，生产使用需增加可证明的安全水位和快照保留策略。

## 验证状态

`leave-all` 的原约定同时规定“仅服务账号退出”“left 群公开 members=[]”及“成员表与网关列表一致”。如果群里仍有外部用户，这三个描述不能按全成员字面同时成立。本实现采用明确的公开视图要求：服务账号全部退出后，本地活动成员投影清空，群为 left；不额外踢走外部用户。结束时保存网关成员列表到 job.state.gatewayMembersAtCompletion，核验其中无任何已知服务账号，外部用户可以仍然保留。失败场景保持失败账号及群主成员关系。此取舍不能表述为退出后所有外部成员也被清空或全成员列表始终相同。

真实 PostgreSQL 隔离 schema 测试覆盖 CAS、终态事务回滚、限流 FIFO、503 队首退避、504 确认/一次重试、双实例发送排他与活跃 worker 恢复保护、重复确认时间稳定、数据库事件写失败重放、群任务、群不可写联动和可变时间线快照分页。远端行为在模块测试中用协议适配器控制；实际 HTTP/SSE、完整跨模块及浏览器验证另由系统测试记录。测试主动回拨 timeout_at 验证阈值分支，不将其声称为真实 5 秒端到端计时证据。
