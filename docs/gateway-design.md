# 网关、账号与消息可靠性

> 代码入口与命令均相对于项目根目录。运行位置、当前演示版本和证据边界见[文档入口](README.md)。

## 模块职责

`gateway/index.ts` 注册 REST 并独立调度账号发送、群任务、限流恢复及事件重试。`accounts.ts` 负责账号操作；`state.ts` 维护跨模块原子状态后果；`messages.ts` 是所有来源共用的发送与成员移除适配；`jobs.ts` 执行持久建群/退群步骤；`events.ts` 接收、校验、重放和去重网关事件。长远端请求只占所属后台任务，不阻塞全局 tick。

## 状态与并发

账号手动变更使用行锁及 expectedFrom 校验。终态、群成员清理、queued 取消、对应序列步骤 skipped 和持久事件在同一事务提交。群不可写同事务停止序列并请求 Agent 在当前步后取消。跨实例使用 PostgreSQL 会话级 advisory lock 排他执行账号发送和单个群任务；连接中断释放锁，但不会据此认定远端副作用没有发生。数据库层监听借出连接错误，将失效信号通过异步执行上下文传递给后续数据库操作和远端请求；旧任务不得在失锁后发起下一次操作，新发送任务拿锁后将遗留 sending 意图转换成 unknown 并查询核验。已到达远端的请求仍可能发生副作用，取消本地等待并不等于撤销远端执行。

## 事务事件顺序与本地重试

事务内的 `emit` 先缓存在当前事务上下文，所有领域行写入完成后，再取得全局事件提交顺序锁并写入事件，随后提交。这样持有事件锁的事务不再等待账号、群或成员行，消除“终态发送先占事件锁再清成员，成员事件先占成员锁再发事件”的锁顺序环。事件与领域写入仍在同一事务，回滚不会留下公开事件。

同账号出站FIFO按消息第一次 `message` 事件的seq排序，该seq在事务收尾分配，反映实际提交顺序；不能用事务开始时间或较早的入队动作排序。迁移 `004_message_event_order.sql` 为事件payload.id和seq建立部分索引，避免每次队列读取全扫事件。已接收的远端结果若落库遇到PG `40P01` / `40001`，只重试应用该结果的本地事务，最多三次尝试、间隔25/50ms；远端send不会放入该重试回调，也不会因此重复调用。T01–T03分别验证终态/成员并行、已知结果本地重试和“先入队但后提交”的FIFO顺序。

## 发送、超时与恢复

发送先写 outbox，远端调用前保存 dispatch intent。只有已知 NETWORK_TIMEOUT 响应才开启 2 秒否定确认窗口；否定确认必须来自窗口结束后发起的查询，明确仍为 404 时才使用同一 clientMsgId 最多重发一次。窗口内发起的查询即使在窗口结束后才返回 404，也只代表较早的观察，不能据此重发；下一轮重新查询。重发前持行锁核对消息仍为 unknown / uncertain，且持久化 timeout_at 仍对应本次确认。查询不可用维持 unknown；已落地的查询或事件更新为 sent。没有已知 504 的进程中断/传输超时只查询，不自动重发。503 作为明确不可用响应退回待处理状态，后退 500ms 重试。

协议没有全局请求去重，不能证明任意崩溃下全局恰好一次。创建群响应丢失也没有结果查询接口；此类任务保留 running 并提供 recoveryNote 及 inconsistency，等待核验。kick 返回 504 后查询成员；目标仍在时无法区分未移除与移除后重新入群，不盲目重试。未确认结果不伪装成成功或确定失败。

## 事件与分页

SSE 从 since=0 重放全部历史，在业务事务内依 event_id 去重。失败事件不被标记成功，可在当前进程重试，重启后从网关完整历史恢复；inconsistency 在数据库可写后持久发布。自己的回流通过 by-client-id 关联到稳定 outbox id。成员事件先取得群行锁再查询网关当前列表，退出任务与kick末端删除使用相同群锁，避免迟到快照覆盖新删除。插入服务账号成员前在事务内取得账号共享锁并重读状态；终态账号和left群不能被迟到member_joined或ALREADY_MEMBER重新加入。事件重试取出后先移除，失败再排到队尾，避免前20个持久失败阻塞后续已恢复事件。时间线首次请求持久化完整快照；后续 cursor 使用快照及偏移，快照内容和顺序固定。新消息及状态变化由实时视图按稳定 id 合并。该方案优先演示规模正确性，历史重放及快照存储成本随历史增长，生产使用需增加可证明的安全水位和快照保留策略。

## 验证状态

`leave-all` 的原约定同时规定“仅服务账号退出”“left 群公开 members=[]”及“成员表与网关列表一致”。如果群里仍有外部用户，这三个描述不能按全成员字面同时成立。本实现采用明确的公开视图要求：服务账号全部退出后，本地活动成员投影清空，群为 left；不额外踢走外部用户。结束时保存网关成员列表到 job.state.gatewayMembersAtCompletion，核验其中无任何已知服务账号，外部用户可以仍然保留。失败场景保持失败账号及群主成员关系。此取舍不能表述为退出后所有外部成员也被清空或全成员列表始终相同。

真实 PostgreSQL 隔离 schema 测试覆盖完整 36 种账号状态组合、CAS、终态事务回滚、限流 FIFO、503 队首退避、504 确认/一次重试、双实例发送排他与活跃 worker 恢复保护、锁连接丢失后的就地接管、重复确认时间稳定、数据库事件写失败重放、群任务、群不可写联动和可变时间线快照分页。专项错误验证覆盖 SESSION_EXPIRED、异步 message_failed、ACCOUNT_OFFLINE 与 SENDER_NOT_IN_GROUP 的状态传播范围。

多数远端行为在模块测试中用协议适配器控制；kick 的请求、504 等候、成员查询取消使用真实 HTTP 和调用方预算信号。核心连接测试仅终止各测试拥有的 PostgreSQL backend PID，验证进程不中断、在途 HTTP 取消、旧任务后续操作被拒绝及新任务可恢复，不重启数据库容器。实际 SSE、完整跨模块及浏览器验证另由系统测试记录。

真实 HTTP 延迟否定响应回归：约 0.7 秒时查询尚未落地的消息，保存 404 结果并延迟 1.55 秒返回；原消息约 1.6 秒时落地，测试不投递 SSE。系统不能使用约 2.25 秒才返回的旧 404 重发，必须用窗口后发起的新查询确认原消息。验证远端发送和落地均只有一条，且未消耗重试额度。

阈值分支测试主动回拨 timeout_at；另有不修改时钟的测试，两个即时 504 且查询均返回 404 时约 4.4 秒确定失败，远端 send 调用总数为 2。该时序证据只覆盖可及时响应的模拟远端。查询不可用时保持 unknown；如果重发响应本身过慢，第二次未知发送仍须等待约定的否定确认，不能为满足 5 秒表面指标而提前宣告失败。

已确认的kick/leave成功属于历史操作证据，不代表响应到达时目标仍未入群。后续在群锁下重新读取当前成员列表，只对当前确认不存在的成员删除本地投影；重入成员保留。若成员GET失败，kick保留已确认成功并发一致性提醒，leave保存已确认进度并记录刷新失败、阻止群主继续退出；成员事件重试或历史重放负责收敛，不重放原kick/leave。退群最终检查同样在群锁取得后读取当前列表。
