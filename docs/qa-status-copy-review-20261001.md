## 检查准则

1. 状态标签应对应持久化状态，区分运行状态和消息投递状态；已受理、已发送、结果未知不能互换。
2. 说明必须准确限定对象，不能把当前工具被阻止写成整次运行从未产生副作用，也不能暗示既往结果被撤销。
3. 已结束或已因恢复限制暂停的运行不能仍使用承诺继续推进的零步骤等待提示。
4. 提示中的可用动作应与实际入口一致；读取重试不能被说明为重发消息或重启运行。
5. 不承诺未实现的自动恢复、结果确定性、重试安全性或时间上限；不把实现限制改写成通过。
6. 明确固定文案、后端产生的提示和外部生成内容的边界；保留历史事实，不通过改写历史结果掩盖旧表述。

### COPY-02：零步骤提示与运行状态一致

修前 `AgentRuns.tsx:193` 仅根据是否没有步骤，统一显示“正在等待第一步结果”。取消可以在首次调用前生效，预算也可以在首次模型调用前耗尽，因此无步骤的终态不应提示继续等待。

修后 `AgentRuns.tsx:195` 至 `:202` 保留现有无步骤分支，只调整标题选择：

| 条件                                               | 展示               |
| -------------------------------------------------- | ------------------ |
| 无步骤、`status=running`、无 recoveryNote          | 正在等待第一步结果 |
| 无步骤、`status=running`、有 recoveryNote          | 暂无步骤记录       |
| 无步骤、`status=cancelled/failed/finished/blocked` | 暂无步骤记录       |
| 有步骤                                             | 仍展示原有步骤列表 |

finished/blocked 零步骤也做防御性渲染检查，不据此声称实际正常流程必然生成这类数据。带恢复说明的 running 不再显示等待，但没有变更其持久化状态、恢复机制或处置入口。
