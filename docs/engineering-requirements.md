## 模块、职责与依赖

后端 Node.js + 严格 TypeScript + PostgreSQL；前端 React 18 + TypeScript + Vite。数据库是业务、任务、发送、Agent 历史、序列进度、事件与恢复记录的事实来源。首版无需 Redis 或重型工作流设施。

| 层/模块 | 职责与接口 | 依赖 |
|---|---|---|
| API 与会话 | 输入校验、统一错误、权限、refresh 轮换、REST/WS | 应用服务、数据库会话与事件 |
| 账号与群 | CAS 状态机、成员、建群与退群任务 | 数据库事务、网关适配器 |
| 统一发送 | 手动/Agent/序列共用的持久队列、限流、未知结果确认、终态 | 账号/群规则、网关 |
| 事件与时间线 | 全历史重放去重、身份合并、稳定快照分页、提交后推送 | 数据库、网关 SSE |
| Agent 编排 | 单群互斥、完整历史、步骤、预算、审计、工具副作用恢复 | 统一发送、群、Agent 协议适配器 |
| 序列 | 预检、变量来源、角色选择、发送后排期、恢复顺延 | 统一发送、群、数据库 |
| 模拟服务 | 独立网关与 Agent、可复现故障控制 | 原始外部协议；控制接口与业务协议分离 |
| 控制台 | 五个页面、只读权限、单次续期、实时合并与断线补齐 | 明确 API 契约 |

接口层、应用编排、领域规则、基础设施适配分工清楚。公共契约、实体、状态与错误类型明确；所有外部输入运行时校验，明显局部允许推导。业务流程由单一职责模块组合，避免巨型函数/类及无收益抽象。关键并发、恢复约束和排查点写解释性注释。日志关联 request/job/message/run 标识；失败、重试和恢复可追踪。

初始三条开发线：A 账号/群/消息可靠性；B Agent/审计/工具/序列；C 控制台/会话/权限/同步。协调者负责共享契约、数据库、调度、模拟器、联调与需求证据矩阵。最多三个执行单元加协调者，尽可能合理并行；仅真实契约/数据依赖和文件冲突串行。文档与决策留痕不阻塞独立开发，不同时编辑共享契约、迁移及入口文件。

## 可证明的保证与协议限制

- 网关不按 clientMsgId 去重。只有明确收到 504 才适用“2 秒收敛后 404 可安全重发一次”；任意请求在返回前崩溃不能由 outbox 或本地锁证明恰好一次。无法确认时保留 unknown 与告警，不盲重试、不虚报结果。
- 建群无幂等键/任务查询；远端成功但本地未保存 groupId 存在不可确认窗口。踢人后重新入群、Agent 同历史请求重放也可能歧义。保留证据与人工确认入口，不更改公开枚举；模拟器额外假设单独说明。
- 乱序和全历史补投不能采用“收到最大 eventId 即安全游标”。首版可从头重放并持久去重，明确历史增长成本。
- 时间线允许任意历史补投及 queued.sentAt 改写；使用稳定内部身份、明确分页快照与后续实时合并，自己消息只一行且不触发 Agent。
- Agent 保存历史、步骤、工具副作用、累计活动时间及待处理消息；单群 running 用数据库唯一约束，不能仅内存互斥。终态、群不可写、限流、序列及群主最后退出共享一致规则。

## Git 与持续协作

每个完整可验收任务尽量独立 `agent/` 分支，必要时使用工具管理的隔离工作树。动手前检查路径、HEAD、status、diff，保留用户改动。任务内小步提交，验证后本地集成并保留历史。原始文件校验不符即停止相关提交并排查。

持续推进已授权工作，不等待文档审阅。需要判断时列选项、建议和影响，同时推进独立任务。已授权且可逆的决定，等待几分钟无反馈后可按推荐方向暂行，记为“暂定、待复核”；执行默认等待 5 分钟只是技术建议，未获逐项确认。明确需新授权的事项继续待确认；不得越过固定约束。重要修订记录改动、原因、影响及替代关系。
