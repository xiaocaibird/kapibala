# 前端可视化操作与交互：已有补强及人工走查欠缺

[返回第三轮规划总表](../third-round-plan-20261002.md)

本节是第三轮优化规划的人工走查部分，当前仅记录和提出方向，不实施、不重新启动 QA。负责人已确认本节定位：现有页面能支撑已实现功能的操作，但面向运营人员日常使用，仍有明显的交互欠缺，缺少完整、连贯的页面交互与操作流程设计。若未来正式供运营人员使用，应重新进行完整的页面 UI、交互及流程设计，围绕查找、理解状态、编辑、复用及跨页面操作系统梳理，而不只逐项修补本表。此为负责人基于初步体验作出的产品判断，不冒称已完成全站可用性研究。七条走查反馈是具体例子，不代表已穷尽全部交互问题。

来源：[人工走查记录](https://chatgpt.com/space/page_7c9626346df88191a0061437187ec469)，及同名对话中负责人逐条反馈。此处已读取对话记录，未重新操作页面复现。新的原因分析和优化思路均为**初步想法，未经初审**；负责人对问题方向的确认不等于对具体方案的批准。过去已批准并完成的补强单独保留，不重复列为待实现，也不由“已实现”推导为全部人工体验通过。

## 本次人工走查发现的七项欠缺

下表“现象/诉求”来自负责人观察；不是新增 QA 判定。除明确的体验预期外，具体原因、范围和方案仍需后续评审。

| 编号 | 现象或诉求 | 使用影响 | 初步方向（未经初审） | 后续要确认的边界 |
| --- | --- | --- | --- | --- |
| UI-W01 | 群工作台搜索、筛选区域经常抖动 | 输入与筛选时视觉不稳定，影响连续操作 | 先区分布局高度变化、组件重新挂载、状态频繁切换；稳定工具区布局与输入状态，后台刷新只更新必要区域 | WebSocket 同步导致重渲染只是用户提出的假设，尚未验证；不应仅关闭实时更新来消除表象 |
| UI-W02 | 群详情中群主排在管理员下面，预期群主第一 | 不易快速理解角色与责任 | 明确群主优先，其次管理员及成员的稳定展示次序；同角色采用稳定排序 | 角色数据来源及其他成员排序需细化；仅调整展示，不改变权限或远端角色 |
| UI-W03 | 群详情部分文字 UI 显示异常 | 阅读和理解信息受影响 | 后续收集具体位置、长文本与窗口尺寸；统一换行、截断、间距和状态标签布局 | 当前没有具体文字和异常截图，不能推断字体、溢出或样式根因 |
| UI-W04 | Agent 运行页面缺少快速筛出有记录群的入口 | 需要逐个群尝试查找运行 | 增加“有运行记录”等查询条件及清晰空态，必要时从运行记录直接按群检索 | “历史有记录”与“当前正在运行”须分别定义；如列表分页，不能只在已加载群中本地筛选 |
| UI-W05 | 序列页面无法快速筛出已有序列的群 | 逐群查找成本高 | 提供有序列运行记录的群筛选，结合运行状态和最近活动作为候选查询项 | 明确历史记录/活动运行/模板关联的含义；共享模板存在不能等同该群已执行 |
| UI-W06 | 变量配置容易清空，需要重复填写，缺少复用 | 重复操作多，也容易填错 | 区分临时草稿与可命名预设；先评估按模板保存变量组合，载入后允许检查和修改 | 先复现清空触发动作；确定用户、群和模板的隔离范围，敏感变量处理及模板改变后的兼容，不跨身份静默恢复 |
| UI-W07 | 同一序列模板缺少方便的跨群快速复用操作 | 在多个群执行相近流程时步骤繁琐 | 先核对现有模板选择与切群能力，再评估保留模板/变量预设、显式切换目标后重新预检的快捷流程 | 不直接写成完全不能跨群使用；是否包含变量、复制与引用的区别、是否批量执行须独立定规则，不能自动沿用旧群预检 |

UI-W01 与既有搜索分页补强可以同时成立：功能已实现，交互稳定性仍可欠缺。UI-W04/05 与旧“更多筛选”方向合并追踪；UI-W06 与变量预设/草稿方向关联；UI-W07 与模板生命周期及预检保护关联，但均保留本次人工观察的独立来源。避免重复建设，也不以旧功能存在否定新的效率诉求。

## 后续设计的组织方式

以运营人员的连续任务为主线：找到目标群 → 理解角色与当前状态 → 配置消息或序列 → 确认目标和效果 → 查看进度与历史 → 再次复用。先补现象和任务场景，再做交互草图及规则评审；确认后才进入实现和独立验收。本次不承诺全站重写，不变更现有业务规则，也不把未走查的后台能力写为人工已验收。
