## 问题来源与总体判断

负责人实际反馈：从 Agent 运行列表进入详情后，页面固定提供“返回群组”，不能返回进入详情前的列表；从群详情进入 Agent 运行详情时，导航选中项和页面标题切到 Agent 模块，浏览上下文不连贯。负责人要求整体检查四个工作区的路由、导航、返回及业务交互合理性。

源码核对确认：目前地址只保存页面和实体 ID，没有统一来源上下文；侧栏选中项及面包屑仅由地址第一段决定，Agent 详情固定链接所属群。工程侧进一步发现的状态恢复、失败页、深链及地址容错问题分别列出，不能都写成负责人亲自发现。

建议以一个小型、类型明确的导航描述统一实际页面、所属工作区、进入来源和返回目标，复用现有页面。只改一个返回链接较小；覆盖全站入口、状态恢复及前进后退后属于**中等范围的前端调整**。当前没有发现必须修改后端、数据库或外部协议的理由，也无需为此更换路由框架。

## 当前链路与问题

| 链路 | 源码事实 | 处理建议 |
|---|---|---|
| 群目录 → 群详情 → 群目录 | 目录已有跨页面 Provider，保留同次登录的查询、分页和卡片位置 | 保留并复用；整页刷新清空是既定规则，不记为新缺陷 |
| 群详情 → Agent 详情 | 与 Agent 列表使用同一个无来源详情地址；侧栏切到 Agent；返回固定所属群 | 保留群工作台上下文，回原群详情，标题仍说明正在查看运行详情 |
| Agent 列表 → Agent 详情 | 详情仍固定“返回群组” | 回 Agent 列表，另保留明确的“查看所属群”关联操作 |
| Agent 列表选择群 → 详情 → 后退 | 所选群仅存列表组件局部状态，卸载后重新挂载会重新选择 | 同标签、本次登录内恢复选中群；实际浏览器回归确认 |
| 群详情 → 定时序列 | 初始地址带群 ID；没有返回原群入口；序列切群只更新局部状态，地址仍是原群 | 增加明确的来源回程；序列操作目标群与地址保持一致，切群后刷新不能回到错误目标 |
| 侧栏 → 服务账号 | 单页，无详情子路由 | 暂无已确认的专属返回问题，参与统一导航和会话回归 |
| 全局提醒 → Agent 详情 | 入口不保存来源，返回仍固定所属群 | 回到打开提醒前的有效站内页面；无来源时使用确定的功能列表回退 |
| Agent 详情读取失败 | 返回链接位于读取成功的内容分支 | 错误、空态和不可访问状态也应有明确返回与重试入口 |
| 业务深链 → 登录 | hash 保留，登录后继续按原地址显示 | 保留该能力；增加无权限、实体失效和身份切换回归 |
| 浏览器前进后退、刷新 | hashchange 恢复地址，没有统一的来源和状态模型 | 区分地址恢复与页面状态恢复，避免称“浏览器后退正常”就代表筛选/选择/位置都恢复 |
| 未知或畸形地址 | 未知 page 回落群目录但导航可能无选中；解码失败可抛错；额外段被忽略 | 统一解析和安全回退；属于源码风险，尚未新增实机故障复现 |

## 初步交互规则

1. **页面内返回优先回到本次进入前的有效站内页面。** 群详情进入则回原群；Agent 列表进入则回列表并保留所选群；提醒进入则回提醒打开前页面。没有来源的直接链接或新标签回功能列表，提供“查看所属群”作为单独关联入口。
2. **工作区选中项与实际内容标题分别表达。** 群内查看运行详情时，群工作台可保持选中，面包屑可为“群组工作台 / 群名称 / 运行详情”；浏览器标签和页面标题仍明确表示 Agent 运行详情。不能把所有“标题”强行当成同一种导航状态。
3. **返回动作不机械等于浏览器后退。** 有可信同应用前序记录才使用后退；直接打开、刷新后来源失效或上一项来自外站时使用确定的站内目标。避免外跳和“返回时又压入一页”导致来回循环。来源只接受结构化、白名单内的站内目标。
4. **导航上下文不改变实时提醒的实体范围。** 群工作台高亮时，运行详情依然按当前 run 判断更新与呈现，不扩大为整个群，也不因导航样式变化就清除提醒。
5. **复用已有状态保留约定。** 群目录查询、分页和位置仍仅限同标签、本次登录内；整页刷新、注销、身份切换清空，不新增 URL 或持久存储中的群目录查询。Agent 列表补同样范围的选择恢复。序列地址已有群 ID，其地址与实际选择应一致。
6. **失败也能离开。** 返回、重试及关联入口不依赖详情成功加载；目标删除、无权访问或来源不可用时给出清晰回退。

实现时可在现有 hash 路由上统一解析/构造、受控来源上下文、返回动作、标题和工作区描述；来源是否保存在当前 history entry 等细节须结合刷新/深链回归确认。已有地址应继续有效，不能仅拼接未经校验的 returnTo 字符串。

## 范围与相邻事项

本方案涉及路由 hook、主布局、运行列表与详情、群详情、序列入口及同会话页面状态。沿用实际业务组件和实体，不复制两份运行详情实现。

本轮不附带全站持久草稿、离页拦截、序列历史页面、全站提醒中心或新的路由框架。草稿保护等相邻问题已有 PI-03/PI-08 等来源，应关联并单独确定范围。当前对路由的反馈与方案不构成上述事项的实施授权，也不撤销此前已单独授权的输入法提示/图标残留修复、C1/C2 工作。

## 实施获准后的验证清单

| 场景 | 应证明的结果 |
|---|---|
| 两种 Agent 详情入口 | 返回目标、所选群、导航高亮、面包屑和内容标题各自准确 |
| 群 → 运行 → 返回，反复前进后退 | 不形成循环，不回错群，不创建重复业务操作 |
| 群 → 序列，序列再切群、刷新和返回 | 地址、表单操作目标和来源回程有清晰且一致的语义 |
| 四个工作区通过提醒打开详情 | 来源可恢复；提醒的实体范围与确认规则不改变 |
| 直接深链、新标签、刷新、登录恢复 | 缺少来源时有确定回退；不会退到外站或继承上一身份的状态 |
| 不存在、拒绝访问、临时读取失败 | 始终能离开当前页；重试不破坏来源和选择 |
| 非法编码、未知路由、篡改来源 | 无未捕获解析异常，无任意外跳，导航状态与实际页面一致 |
| 既有目录与表单 | 搜索、分页、过期提示、卡片位置、请求和已批准的表单保护不退化 |

本节列的是原初步方案的验证范围，不等于本批全部获准。当前两入口的实际实施与证据以[前端交付记录](final-enhancement-ui-20261002.md)和[本轮汇总](final-enhancement-delivery-20261002.md)为准；其余范围继续保留待后续选择，人工验收尚未完成。
