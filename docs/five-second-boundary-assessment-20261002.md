## 3. 当前源码实际保证什么

以下行号固定于 `01f2c1a`：

| 源码位置 | 实际机制 |
| --- | --- |
| [tool-execution.ts](../apps/server/src/modules/automation/tool-execution.ts)，L362–391 | 从实际等待入口进入 `waitForDelivery`，只建立一次单调截止 `now + min(5000, remaining)`；不每次查询重新计五秒 |
| 同文件 L393–443 | 读取原消息；及时确认 `sent` 时跳过账号读取，其他情况读取账号后按原状态映射；无事实不伪造发送失败 |
| 同文件 L444–458 | 及时读取的确定事实优先返回；无新事实则继续原窗口，到期生成 `SEND_TIMEOUT`。该结果不把持久消息改成失败 |
| [delivery-observation.ts](../apps/server/src/modules/automation/delivery-observation.ts)，L76、L134–187 | 取得实际 PoolClient，在只读事务内按剩余时间设置 `lock_timeout <= 50ms`、`statement_timeout <= 100ms`，每条读取刷新；身份 SQL 仅在工程观察启用时执行，耗时计入原窗口 |
| 同文件 L189–240 | 截止前固定已读取事实；等待实际 ROLLBACK 后才复用连接；清理、连接、所有权错误继续传播；不会因清理尾差把及时事实改成未知 |
| [db.ts](../apps/server/src/core/db.ts)，L99–104 | 当前普通连接池最大连接数为 20，没有本工具专属的端到端获取、传输和清理硬时限 |
| tool-execution.ts L245–281 | 真实工具交还与历史保存分开记录；不能把保存开始或返回包装当成真实 COMMIT/ROLLBACK |

这是一套服务端查询有界、结果保守、清理不遗弃的工程等待机制。它没有建立连接池排队、网络传输、事件循环停顿和 ROLLBACK 交还的统一硬上界。`SET LOCAL` 的限时也不等于应用在同一物理时刻获得响应。既有设计和实验边界见 [局部数据库超时说明](agent-delivery-observation-20261001.md)、[读取因果说明](qa-delivery-read-causal-observation-20261002.md)。

对尚未确认的路径，若五秒截止为 D，“到 D 才能认定超时”与“调用者必须不晚于 D 收到结果”同时按严格物理时刻解释，就要求判定与交还没有尾差。当前实现和运行环境没有这种保证。这不是任何计时要求都无法实现的结论，而是不能通过缩短某个常量证明现有两项约束同时满足。

## 4. 局部补丁的收益与边界

以下是可评估的工程方向，**本次未实施**，也不是已经证明可关闭本项的方案。

| 方向 | 可改善什么 | 边界与代价 |
| --- | --- | --- |
| 末轮读取准入，给已发查询和清理留出内部阶段预算 | 避免剩余时间很少仍开始一轮不易及时收尾的数据库读取，减少常见跨截止清理 | 单次读取和清理预算需要明确依据；提前停止新 SQL 会改变尾段可观察性。未知超时仍须到原截止才形成，因此调度及交还尾差依然存在 |
| 减少重复设置、身份查询及事务往返，或复用一次等待内的连接 | 有可能降低局部传输和排队开销 | 需保留每条查询的剩余窗口、账号终态判断、及时 sent 快路及真实清理；长时间占有连接也可能加剧共享池压力，收益须实测，不能凭减少行数承诺 |
| 有界连接准入与独立资源隔离 | 减少共享连接资源被其他工作耗尽时的额外等待 | 超过这两个局部函数的范围；等待取消必须处理后来到达的连接，不能用 `Promise.race` 留下未归属连接或查询；仍不解决任意事件循环和网络停顿 |

原文没有指定连续查询频率，所以“截止前停止发起新 SQL”并非自动等于违约；但它也不能被写成与持续观察完全等价。若尾段的确定状态未被读取，当前调用可能返回未知超时，而同 key 再读才能确认。验证必须包含这条取舍，不能只测一直锁住的超时路径。

以下做法不作为修复：把窗口直接改成 `4990ms` 来匹配本次样本；提前写出 `SEND_TIMEOUT` 后等待发送；改测量起终点、向下取整或伪造时钟；不等待真实 SQL/ROLLBACK 完成；将 unknown 写成 failed；移除 QA 原断言；反复运行直到恰好得到一次通过。

## 6. 后续有效验证要求

若继续做局部改善，应使用固定候选、同一原 run/tool/key、真实数据库和可重现的指定场景，分别检查：

1. 截止前尾段出现 `accepted/sent`、账号进入终态，以及 timely 读取但清理晚返回；明确实际取得了什么事实，不以清理尾差改写它。
2. 持续表锁、连接池不足、真实取消和连接故障、ROLLBACK 失败。记录服务端查询是否已结束、连接是否可复用或销毁，不遗弃在途工作。
3. 原始未知超时的实际形成时刻、实际调用者交还区间、后续真实 step/history COMMIT 分别记录，不互相替代；若仍按原语义，不得在五秒前产出该超时。
4. 同 key 后续读取不重复发送或审计，原消息状态未被超时工具结果改写；保留样本失败和未满足范围。

研发提供候选、观测和资源清理证据，QA 独立维护用例、断言和报告。局部性能改善可以单独成立，但只有符合明确采用的保证并经验证，才能关闭相应项；本评估没有将它提前关闭。
