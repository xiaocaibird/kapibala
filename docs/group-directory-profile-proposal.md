## 2. 目录接口与查询语义

```text
GET /api/group-directory?pageSize=20&order=desc&q=<关键词>&cursor=<续页游标>
→ GroupDirectoryPage { items: GroupDirectoryItem[], nextCursor: string | null }
```

| 项目 | 契约与边界 |
|---|---|
| `pageSize` | 整数 1–50，默认 20；每次返回不超过请求页大小 |
| `order` | `asc` / `desc`，默认 `desc`；只改变创建时间主键方向 |
| `q` | 可省略；trim 首尾，全空白等同无搜索；内部空格保留，不拆词；trim后最大500并拒绝NUL |
| 匹配 | 名称、简介、`gatewayGroupId`、平台 `id` 任一字段包含整段关键词即可；忽略大小写；null 文本按空值处理。`%`、`_`、反斜线须转义为 SQL 字面字符，不是通配符；不承诺拼音、分词或语言学等价 |
| 顺序及边界 | 数据库 `created_at` 按指定方向，再按平台 `id ASC`；游标保留 PostgreSQL 微秒精度的时间边界，不能由浏览器毫秒化的显示值重新生成。改名、改简介不改变创建时间 |
| `cursor` | 第一页省略，后续只使用接口返回值；严格校验v1、字段及值，绑定保留原大小写的trim后`q`、`order`、`pageSize`，不能拿旧条件游标继续新条件；时间边界保存UTC六位微秒 |
| 鉴权 | 每次请求仍验证当前登录身份；admin/viewer 均可读。游标不是授权凭据，Base64 等编码不构成安全签名，不能绕过鉴权或输入校验 |
| 返回值 | item 含 `id`、`name`、`description`、`createdAt`、`gatewayGroupId`、`status`、`agentEnabled`、`activeSequenceRunId`、`activeAgentRunId`、`memberCount`；不组装整个成员数组。`nextCursor=null` 表示该次查询未发现后续页，不返回 `total` |

后端实施选择是先用有界materialized page CTE取目录页，再在同一SQL汇总成员数及活动run，避免新接口沿用旧全量列表的逐群详情查询。查询有界是实现目标；实际执行计划、耗时及容量只在有证据后登记，不把结构选择当作已测性能收益。

这是正常活数据的 keyset 分页，**不是一次冻结全集的快照**。无并发变化时，两种方向都应完整遍历且无重复；跨页期间新增群、资料改变导致进入或离开筛选集，可能改变后续结果，不能承诺固定总数或永久无遗漏。客户端识别变化后按下节使整份多页列表过期，避免把旧页与新首页拼成一份看似完整的新结果。消息时间线继续使用原快照语义。

## 3. 页面状态、刷新与返回

搜索使用延迟查询并配合输入法组合事件；组合输入期间不提前发查询，确认候选后再查询。换关键词或方向后从第一页开始，旧条件的迟到响应不得覆盖新条件。清除只清关键词、保留方向；搜索、刷新和轮询不抢输入焦点。

| 情形 | 行为 |
|---|---|
| 首次请求中／首次失败 | 分别显示加载态／失败和重试入口，不显示“没有群”的成功空态 |
| 成功空结果 | 空关键词可显示尚无群；有关键词显示无匹配及清除入口，不宣称系统完全无群 |
| 加载更多 | 使用当前条件的下一页游标，按稳定 ID 合并；显示“已加载 N 个群”，不把 N 称为全部或匹配总数；无后续游标时结束 |
| 只有一页 | 每 5 秒及相关实时变化触发有界自动刷新；合并并发失效，避免一条事件触发一次无界读取 |
| 已有多页 | 相关变化使整份列表过期，立即停止旧 cursor 续接并显示刷新入口；5 秒轮询至多做有界首屏探测，不逐页重读全部已加载历史。探测发现变化同样标过期 |
| 整体刷新 | 用户刷新成功后整体替换为新第一页，再由用户决定加载更多；不把新首页和旧后页混合。失败保留旧列表及条件，明确旧数据／失败状态，仍禁止过期游标续接 |
| 无关实时事件 | 不因与目录展示及筛选无关的消息等事件遍历目录；相关字段变化或连接恢复按上述有界规则处理 |

关键词、方向、已加载页、最近打开群 ID 及位置只保存在**同一标签页、本次登录的内存**。从详情返回、浏览器后退或切其他工作区页面后返回时恢复这些状态；返回按稳定 ID 尽力定位，不使用易变数组索引，也不自动无限加载直到找到原群。若原群已不匹配、不存在或不在可恢复页中，保留条件并明确无法恢复原位置，不偷偷清空搜索或冒称像素完全一致。

整页刷新、注销、身份切换清空该状态；这些目录查询条件与页不写 localStorage/sessionStorage，不增加 URL 搜索历史；原有创建任务jobId的`kapibala:createJob` sessionStorage跟踪属于既有独立能力，应保留跨整页刷新找回并捕获存储异常，不能因此把已受理创建误报失败。028a2e8已恢复该兼容边界并通过独立任务reload/隐藏找回验证；真实浏览器存储拒绝未执行，异常捕获只有源码审阅证据。新标签打开详情没有原列表位置可恢复。缓存数据仍受过期规则约束，不能因为返回缓存就把旧页称为最新；手动整体刷新成功后仅保留新的第一页。

## 4. 资料摘要与两处表单

卡片保留名称优先、无名称回退网关群 ID、创建时间本地展示和同名群 ID 区分；简介作为最多两行的纯文本摘要，完整内容在详情查看。无简介不编造内容，也不保留两行空白占位；命中简介时可简单截取命中附近的纯文本局部片段，提示匹配来源；不增加独立摘要字段、富文本、高亮HTML或分词/相关度算法。

表单关闭保护只覆盖群创建与编辑资料的关闭路径：无改动直接关闭，有未提交改动时选择继续编辑或放弃修改；请求提交期间限制关闭，失败保留输入。组件因页面或身份变化卸载后，忽略迟到成功／失败响应，不再修改新页面或显示旧表单结果。忽略响应不表示已取消服务端创建或保存，不自动重放原写请求；这不是全站路由阻止、浏览器退出保护或持久草稿功能。

现有输入规则暂沿用：名称 trim 后 1–80、已填写名称不能清空；简介 trim 后最多 500，空字符串清空为 null，PATCH 显式 null 仍不接受；均按现有 JavaScript 字符串长度。80/500 及不可清空仍是已有实现选择，本次保留不等于用户将其确认为长期业务限制。创建资料可选，旧字段为空不编造；仅 PATCH 改变的字段，不覆盖省略字段；同字段多管理员写入仍最后写入生效，不新增 CAS。
