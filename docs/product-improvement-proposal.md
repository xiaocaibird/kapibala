## 3. 逐项方案

编号 PI-01 起稳定引用。分类：**缺陷候选**为实现或表达偏差，需复现确认；**体验补全**为既有范围内改善；**新增能力**需单独授权；**原有可选扩展**保持原范围。优先级：P1 影响意图、判断、数据或权限，优先核实；P2 影响效率和可追踪性；P3 为规模或扩展选项。本次未观察到需要直接宣布全面停用的 P0 事实。

### PI-01 账号操作与两层“管理员”角色说明

- **问题与证据：** 源码 [Accounts.tsx](../apps/web/src/pages/Accounts.tsx) L54–63、157–163 的状态操作调用 API；[accounts.ts](../apps/server/src/modules/gateway/accounts.ts) L74–78 在离线/释放路径调用网关 disconnect。O3 已有终态/限流提示。群成员中的 admin 与登录用户 admin 属于不同权限层。
- **影响与原因：** “标记离线”容易被理解为仅记备注，“释放”容易被理解为删除；群管理员身份也不能直接赋予控制台操作权限。操作引起真实连接变化，可能影响正在等待的发送。
- **建议与恢复：** 在按钮旁或一次说明中写明“断开网关连接”“释放为待连接，保留历史”；明确控制台管理员执行管理、群内角色决定服务账号的发送/移除能力。CAS 冲突保留错误并查询最新状态，要求重新判断，不自动用新状态重复原变更；终态明确不可恢复。不要增加通用的“强制在线”。
- **分类/优先级：** 体验补全，P2；少量说明即可，已有状态机不重做。
- **最小成本/依赖：** 前端说明与错误映射，约 1–3 小时；依赖现有状态和错误码。
- **验收/待决定：** 离线、释放、重连的作用能区分；CAS 冲突不自动提交第二次；viewer 无写入口且直接请求仍拒绝。待决定是否只补说明，或在有相关运行时加轻量影响确认。

### PI-02 群查找、筛选与排序范围

- **问题与证据：** O1；[Groups.tsx](../apps/web/src/pages/Groups.tsx) L62–123 直接显示全部卡片，无查找；[gateway/index.ts](../apps/server/src/modules/gateway/index.ts) L141–147 返回全量，排序 `created_at DESC,id` 已存在。
- **影响与原因：** 名称有助辨认，但同名、无名、长 ID 和较多群仍难定位；群状态与 Agent 状态是现成的筛选维度。
- **建议与恢复：** 首版对已取到的完整列表增加名称/本地 ID/网关 ID 关键词与群状态筛选，展示匹配数和清除条件。无匹配不能显示“还没有群”。排序注明依据和方向；是否允许切换升降序由用户选择。无名群保留编号、同名群保留区分信息。
- **分类/优先级：** 体验补全 P2；响应用户触发问题，适合批次 B。后端分页/全局检索是新增能力 P3，当前 4 群没有性能紧迫证据。
- **最小成本/依赖：** 当前列表过滤约 2–4 小时，无数据库变动；服务端分页另估，不连带承诺。
- **验收/待决定：** 名称、两个 ID、同名旧群均能找回；清除条件恢复列表；刷新后排序稳定。待决定默认方向、第一版筛选维度；不改变 CR-003 的待确认状态。

### PI-03 表单关闭、未保存输入与同字段并发

- **问题与证据：** [CreateGroup.tsx](../apps/web/src/components/CreateGroup.tsx) L49、150–155 与 [Sequences.tsx](../apps/web/src/pages/Sequences.tsx) L464、497–507 的底部取消忙时禁用，但通用 [ui.tsx](../apps/web/src/components/ui.tsx) L239–247 的 Esc/关闭仍调用 onClose。[GroupProfile.tsx](../apps/web/src/components/GroupProfile.tsx) L64–90 已有 busy 保护和局部字段更新，但 dirty 关闭不提醒；[gateway/index.ts](../apps/server/src/modules/gateway/index.ts) L171–181 同字段最后写入生效。
- **影响与原因：** 提交后关闭不等于撤销后台请求，重新创建可能重复；误按 Esc 丢草稿；两个管理员同改名称可覆盖，改不同字段已有保护，不应夸大为全量覆盖缺陷。
- **建议与恢复：** 保存中统一限制关闭，明确请求仍在处理；dirty 关闭提供“继续编辑/放弃”，默认不落盘草稿。错误定位到字段，保留输入。若实际需要同字段冲突保护，再加 expected value/version 与冲突比较；先 GET 对比不能提供原子防覆盖保证。名称可否清空、长度限制单独确认。
- **分类/优先级：** busy 关闭为缺陷候选 P1；dirty 保护与规则明确 P2；原子并发检测为新增能力 P2。
- **最小成本/依赖：** 关闭与 dirty 保护约 2–4 小时；同字段版本校验另约半天至一天，涉及契约及并发验证。不建协作编辑系统。

### PI-09 浏览器提交结果未知与请求幂等

- **问题与证据：** [client.ts](../apps/web/src/api/client.ts) L46–61 网络异常统一提示“请稍后重试”；[gateway/index.ts](../apps/server/src/modules/gateway/index.ts) L194–206 手动发送只收账号/文本，[messages.ts](../apps/server/src/modules/gateway/messages.ts) L94–107 每次生成新记录；[jobs.ts](../apps/server/src/modules/gateway/jobs.ts) L38–50 每次创建新 job。后台同一 outbox 的可靠重试，不能去重浏览器的两次独立 POST。

- **建议与恢复：** 提示版区分读请求失败与写请求结果未知，保留目标/正文，指向时间线或同一任务核实；不要把“重新查询”写成“重新发送”。完整新增能力：一次操作生成 request key，服务端与业务记录同事务持久映射，唯一约束处理并发；同 key 同 payload 返回原结果，同 key 不同 payload 拒绝。key 绑定操作者及操作范围，并先鉴权；不能由文本相同判断重复，合法重复发送应使用新 key。这只解决平台接收层，不解决网关未知窗口。
- **分类/优先级：** 错误提示补全 P1；持久请求幂等是新增能力 P2，若复现造成实际重复可提高实施优先级。
- **最小成本/依赖：** 提示版约 1–3 小时；完整幂等约 1–2 天，涉及接口、存储、并发与旧调用兼容，不能挤入小文案改动。
- **验收/待决定：** 隔离丢失 POST 响应后不出现确定失败断言；完整方案须证明双提交只产生同一记录、权限仍验证、重启后映射保留、同文本新操作仍可发。待决定本轮仅提示，或批准幂等的端点范围及保留策略。

- **问题与证据：** [Sequences.tsx](../apps/web/src/pages/Sequences.tsx) L122–132 的预检只传 sequenceId/vars/stepVars，L332–395 的弹窗展示文本和变量来源，缺目标群、模板名、角色和延迟摘要；[sequences.ts](../apps/server/src/modules/automation/sequences.ts) L188–193 只做变量解析，执行 L528–548 才判断角色缺失或限流。

- **建议与恢复：** 标题改为“变量预检通过”，展示目标群名称+ID、序列名称、各步角色与相对延迟；保留最终文本、最终值和来源，说明第一步从启动计时，后续从上一条确认发出/跳过后计时。角色可用性快照可选，不改变运行时选择和跳过规则。仅在 `409 SEQUENCE_ALREADY_RUNNING` 时重新查询群的 activeSequenceRunId，仍存在才提供入口；已结束则说明状态变化。`GROUP_UNREACHABLE` 按群不可写处理，不把所有 409 都引向已有运行，也不自动再启动。
- **分类/优先级：** 范围内体验补全 P1 小版；角色快照增强 P2。
- **最小成本/依赖：** 用已有页面数据约 1–3 小时；角色状态查询另约半天，无需重写调度。
- **验收/待决定：** 启动前能核对目标/文本/角色/时序；预检通过仍明确可能跳过/顺延；启动时后端复检保留，未解析变量一条都不发。待决定是否增加角色快照警告。

### PI-15 序列变量输入的可理解性与校验

- **问题与证据：** [Sequences.tsx](../apps/web/src/pages/Sequences.tsx) L27–65 使用 JSON schema 和首个错误路径，L105–115 已提取占位符；L265–285 已说明两种空串、分步覆盖延续，并有分步 JSON 示例。这些现有说明不列作缺失；仍可补的是与所选模板相关的示例、JSON 语法位置及更直接的键值输入。
- **影响与原因：** JSON 合法不等于业务值完整；分步覆盖的延续与两种空串语义容易混淆。泛称格式错误不足以指出行/字段，而直接改成复杂拖拽编辑器投入过大。
- **建议与恢复：** 保留现有空串/继承说明和最终值/来源预检，新增与当前模板有关的最小例子及语法位置/字段定位。可选将默认变量改为按占位符生成键值输入，保留高级 JSON；不默认新增模板编辑/版本系统。错误保留输入，修正后重新预检；预检不是发送，不产生恢复副作用。
- **分类/优先级：** 体验补全 P2；完整可视化模板编辑为新增能力 P3，建议后置。
- **最小成本/依赖：** 提示/错误定位约 2–4 小时；键值输入约半天至一天，需与现有 parser 同语义。
- **验收/待决定：** 缺变量定位 stepIndex/key；stepVars 空串不覆盖、前步覆盖延续能从预检看出；错误不丢输入。待决定保留 JSON 加解释，还是采纳简单键值表单。

### PI-16 序列“已处理”不是“已发送”

- **问题与证据：** [sequences.ts](../apps/server/src/modules/automation/sequences.ts) L495–509 对 sent 记录确认观察时间、对 failed/cancelled 也写步骤 sent_at；[SequenceProgress.tsx](../apps/web/src/components/SequenceProgress.tsx) L53–59 除 skipped 外统一标“实际发出”。API L281–293 没有失败原因/等待原因；unknown 或限流可能仅显示待执行。
- **影响与原因：** 失败处理时间被看成送达证据，pending 不足以区别等待计划、限流和未知投递；最终 finished 也不能仅凭“已处理”统计推出每步发出。
- **建议与恢复：** 不改存储即可先按状态标“确认发出时间/跳过时间/失败处理时间”；pending/accepted 无确认时间时写“尚无确认发出时间”，只有可证实未入队才说“尚未执行”。汇总 sent/skipped/failed 数而不是把进度当成功率。增强版联查消息 deliveryStatus/failCode，解释等待；无历史跳过原因标未记录。unknown 只核实，跳过/失败不提供不加区分的“重发全部”。
- **分类/优先级：** 时间标签为表达缺陷候选 P1；原因贯通 P2。
- **最小成本/依赖：** 标签/统计约 1–3 小时；原因联查约半天至一天，未来跳过原因若需持久化另评审。
- **验收/待决定：** 成功、失败、跳过分别展示真实含义；失败不出现“实际发出”；限流与未知分开；重启后只有最早到期步骤按既有规则顺延，不因页面恢复补发全部。待决定本轮仅修标签，还是一起补原因。

### PI-17 已结束的序列运行仍可检索

- **问题与证据：** O5 未显示已有历史进度；[Sequences.tsx](../apps/web/src/pages/Sequences.tsx) L83–104 使用 activeSequenceRunId 或 sessionStorage 的每群一个 runId，L149–152 新运行覆盖旧引用；[sequences.ts](../apps/server/src/modules/automation/sequences.ts) L260–296 只有按 ID 查询运行。
- **影响与原因：** 换标签/会话或再次启动后，数据在库但入口丢失，viewer 也无法自然找到最近的结束结果；“尚无序列运行”事实上只是“当前没有可定位的运行”。
- **建议与恢复：** 最小提示先改准；新增群下“最近 N 次运行”读取接口，按真实创建时间+稳定 ID 排序，提供独立详情 URL，显示模板名、状态、时间。先不做全局任务台；历史筛选若只覆盖最近 N 条要明示。GET 打开原 run，不启动新 run 代替查历史。
- **分类/优先级：** 文案补全 P2；持久列表为新增能力 P2。
- **最小成本/依赖：** 文案很小；API/契约/路由/列表约半天至一天；数据已存在，需核实历史模板关联，不猜旧运行内容。
- **验收/待决定：** 新会话能找到最近已结束运行；第二次执行不遮住第一次；viewer 可读；运行已不存在与加载失败分开。待决定列表数量、是否本轮实现分页。

### PI-18 初次失败、真实空白、旧数据和实时连接

- **问题与证据：** [Groups.tsx](../apps/web/src/pages/Groups.tsx) L46、68–76 可在请求失败时同时显示“从第一个群组开始”；[GroupDetail.tsx](../apps/web/src/pages/GroupDetail.tsx) L33、111 将账号查询失败的 null 当作空数组传给发送框，未呈现 accounts.error。[live.tsx](../apps/web/src/state/live.tsx) L83–86 握手成功即 live，尚未等消息快照完成；时间线有 syncing，但全局“实时同步中”不等于所有依赖数据新鲜。
- **影响与原因：** 暂时读不到被误解为没有群/没有可用账号；WS 通不代表 REST 成功。用户可能重建数据、切换账号或依据旧成员执行操作。
- **建议与恢复：** 区分加载、首次读取失败、成功空值、有旧数据但刷新失败；保留旧数据并注明“更新失败/最后成功读取时间”。依赖账号读取失败时明确原因、禁用未确认身份操作、提供“重新读取账号”。连接标签仅表示连接，页面另表明数据补齐；恢复只读请求不清草稿、不自动重放写入。
- **分类/优先级：** 状态表达缺陷候选 P1。
- **最小成本/依赖：** 约 2–6 小时，涉及资源 hook 的轻量时间信息和页面分支；不重写现有重试协调器。
- **验收/待决定：** 首次 503 不展示创建首群指导；账号 GET 失败不伪称无账号；WS 恢复但 REST 仍失败时保留异常；请求恢复不需要发送新消息来推动。待决定首批仅纠正空态，还是同时显示成功读取时间。

### PI-19 告警关闭后仍保留排查线索

- **问题与证据：** [live.tsx](../apps/web/src/state/live.tsx) L28、94–103 的 notices 为内存且只保留最后 8 条；事件 seq 存 sessionStorage；[App.tsx](../apps/web/src/App.tsx) L140–178 提醒可关闭，仅 runId 提供详情链接。事件本身已持久化，刷新不保证旧提醒重新出现。

- **建议与恢复：** 首先把“关闭”说明为隐藏，展示已知对象 ID/错误码与对应详情入口，提供小型诊断摘要复制；不默认复制完整消息和原始响应。需要更长回看时增加最近异常只读列表，明确范围。人工已查看标记若未来添加，不得修改业务结果。

- **验收/待决定：** 隐藏不取消运行/清错误；重开可找到原记录（仅在采纳列表后承诺）；复制摘要含来源时间及 ID，不带认证信息。待决定仅对象链接，还是近期异常列表。

### PI-20 会话过期、多标签身份和实时故障分流

- **问题与证据：** [client.ts](../apps/web/src/api/client.ts) L16–18、95–119 的 refresh 单飞只在一个页面上下文；[auth.ts](../apps/server/src/core/auth.ts) L111–139 对重用 refresh 撤销整会话。共享 Cookie 的两个标签可能同时用旧 token，属**推断/待复现**。续期只更新 token，而 [state/auth.tsx](../apps/web/src/state/auth.tsx) L38–41、55–61 仅在初始恢复/显式登录时取 user，跨标签换角色可能令界面身份与有效 token 不同；这不等于后端权限绕过。[realtime.ts](../apps/server/src/core/realtime.ts) L49–76 将数据库异常也统一关闭为 4401，前端 L108–123 据此续期。
- **影响与原因：** 双标签突然掉线，或页面显示管理员但写入被真实 viewer 权限拒绝；基础设施错误被误判为认证错误。会话失效卸载工作区（[App.tsx](../apps/web/src/App.tsx) L30–35），组件草稿会丢失。
- **建议与恢复：** 本机同源浏览器明确采用单一当前身份；若支持多标签，协调续期、登录与注销，续期后核对身份，身份改变中止旧操作并刷新权限/数据。不将 token 存 localStorage，不取消重放撤销规则。只有真实认证失败触发认证续期，临时存储异常走退避重连。会话失效给明确原因，重新登录只恢复路由；若采纳草稿保留，按用户+实体隔离，只恢复文本不自动提交，换身份不继承。
- **分类/优先级：** 会话并发/身份一致性缺陷候选 P1（先复现）；WS 分类补全 P2。
- **最小成本/依赖：** 双标签完整协调约 1–2 天；WS 错误分流约半天至一天，需认证/实时专项回归。当前验收可分别用独立浏览器上下文验证角色，不能把操作规避写成问题已修复。
- **验收/待决定：** 双标签并发恢复、真实过期时 REST+WS 续期不误撤销；跨标签角色切换后显示与实际一致；注销后旧 access 与 WS 失效；暂时 DB 故障不无故改身份；旧请求不得自动以新身份继续写。待决定本轮多标签支持范围及草稿策略。

### PI-21 权限、输入展示、审计及诊断信息安全

- **问题与证据：** 已有保障：[auth.ts](../apps/server/src/core/auth.ts) L72–78 统一拒绝 viewer 业务写 API，认证续期与自身注销不属于此限制；[realtime.ts](../apps/server/src/core/realtime.ts) L29、53 持续鉴权；消息/简介以 React 文本显示，见 [Timeline.tsx](../apps/web/src/components/Timeline.tsx) L125、[GroupProfile.tsx](../apps/web/src/components/GroupProfile.tsx) L36–37。风险待查：[remote.ts](../apps/server/src/core/remote.ts) L29–46 保留远端错误 body，[app.ts](../apps/server/src/app.ts) L21–24、75 无显式脱敏且记录 err；是否经序列化写出敏感字段未实测，不能称已泄露。Agent 原始响应与输入当前可被 viewer 读取，是既有权限范围，不自动视为漏洞。
- **影响与原因：** 新“恢复”按钮若只靠隐藏会绕开产品权限意图；错误/原始响应可能含业务文本或凭据样本，复制日志比读取页面扩大传播。审计 pass 是执行前许可，不是消息结果或完整人员追责记录。
- **建议与恢复：** 保留后端统一鉴权与文本渲染，任何新增查询/恢复端点逐一验证权限。输入约束在前后端对齐，字段报错不回显凭据；恶意 HTML 作为文字。先明确 viewer 诊断读取与外发范围，再对错误日志定义必要字段/长度及凭据脱敏，保留关联 ID。原始响应按需展开并标截断，不自动导出全部内容。原始审计记录只追加解释，不允许界面改为 pass 强行恢复。
- **分类/优先级：** 现有保障的验证补全 P1；诊断最小脱敏和共享范围 P2。未证实权限绕过或实际泄露。
- **最小成本/依赖：** 聚焦权限、恶意输入及哨兵日志检查约半天；修正视复现结果估算。固定本地两账号场景不扩展为租户/RBAC/完整审计平台。
- **验收/待决定：** viewer 直接调用每个新增写端点均 403，无未授权副作用；过期/撤销 WS 不再继续有效订阅；HTML/脚本文本不执行；独立错误样本的应隐藏哨兵不进入日志/复制结果且 ID 可排查。待决定 viewer 是否保留同等诊断阅读权限、是否需要外部分享日志。

### PI-22 旧页面、旧数据与备份恢复是同一条交付链路

- **问题与证据：** [migrate.ts](../scripts/migrate.ts) L12–39 有事务/锁，[app.ts](../apps/server/src/app.ts) L31–43 在 schema 不符时拒启；群资料采用 nullable 增量迁移并已有旧库验证。新 [schemas.ts](../apps/web/src/api/schemas.ts) L40–55 要求名称/简介/createdAt，不能把新前端接旧后端当作必然兼容。既有备份证据证明归档可读及复制哈希，不等于独立实际恢复演练。[live.tsx](../apps/web/src/state/live.tsx) L36–38、90–93 存 seq，[realtime.ts](../apps/server/src/core/realtime.ts) L31–39、59–60 直接使用 sinceSeq：旧备份事件水位低于旧页游标时，可能握手成功却要等水位追上才继续推送，属**推断/待复现**。
- **影响与原因：** 保留数据库不保证未提交表单或旧页面兼容；回滚数据库也不能撤销远端已发消息。只恢复本地库而不核对模拟器/外部状态，会产生副作用与记录的不一致；普通刷新也可能保留 sessionStorage 高游标。
- **建议与恢复：** 下一次更新前形成简短清单：目标源码/schema、备份时点与进行中任务、数据库和模拟器配套状态、旧页兼容、草稿提醒、更新后只读核验。恢复演练使用独立数据库和独立模拟器，先暂停后台副作用执行，核对恢复记录和待执行意图后才在隔离环境继续；不得指向当前演示或真实网关，也不能在演示库试恢复。若支持旧页跨恢复，增加事件代际/游标重置与重新快照协议；临时人工流程须明确清理旧游标并重新认证，不声称自动恢复。真实外部网关不可随本地备份回滚，恢复后须先核验未知副作用，不自动重发。
- **分类/优先级：** 升级恢复流程与验证补全 P1（下一次更新/恢复前）；事件代际为新增机制 P2。
- **最小成本/依赖：** 清单及隔离恢复演练约半天至一天；代际协议再约半天至一天，需要 REST/WS/前端协作。本文只提出，不执行迁移、备份恢复或重启。
- **验收/待决定：** 同版本恢复后记录/任务可核对；人工方案执行明确的游标清理/重新认证后可接收新事件，采纳代际协议时旧页无需人工清理即可重建快照并持续接收；旧请求不覆盖新字段；新旧不兼容显示版本错误且无假成功；旧名称/简介/时间不编造，重新执行迁移幂等。待决定本轮只做演练与明确手工流程，还是实现跨恢复的事件代际。

### PI-23 原有可选扩展与明确后置范围

- **问题与证据：** 原 C1/C2/C3 和[需求矩阵](requirements-matrix.md)明确媒体归档、真实模型、完整 Playwright 未启用。O4 的 Agent 流程来自当前模拟服务，不能包装成真实模型接入；现有聚焦浏览器验证不等于完整 C3。
- **影响与技术取舍：** C1 带来文件过期/清理与引用一致性，C2 带来模型输出和真实调用成本，C3 增加自动场景覆盖；它们与本报告发现的草稿/状态文案问题不同，不应靠“加扩展”掩盖基础缺口。
- **建议与恢复：** 保持独立可选范围。若只选一项支持本轮可靠性，可评审 C3 的核心用户路径自动化，并覆盖本次确认的交互风险；C1/C2 等基础验收稳定后再评估。C2 继续工具校验/审计，失败不允许模型绕过；C1 删除策略不能留下失效引用。未知结果仍走原核验路径。
- **分类/优先级：** 原有可选扩展 P3，不作为 A/B 缺陷，不默认必做。
- **最小成本/依赖：** C3 的小规模核心路径约半天至一天以上，取决于隔离夹具；C1/C2 先明确范围再估，不给精确承诺。依赖基础流程稳定与用户明确授权。
- **验收/待决定：** 各扩展使用独立场景和证据，不把模拟器结果写成真实模型结果；C3 无副作用污染演示数据。待决定本轮是否选择任何 C 项；默认继续未启用。

## 4. 验证与取舍：先证明，再决定实施

本报告中的验收标准均为**未来验证要求**，没有被本次只读观察自动勾选。缺陷候选先在隔离环境构造相应数据/网络窗口，确认后才安排修复；不要在用户正在使用的 5173、API3100 或默认数据库中注入故障。

| 验证组合 | 需要证明的关键事实 | 证据形态与范围 |
|---|---|---|
| 消息提交与草稿 | 选定身份失效、慢回包编辑、POST 响应丢失后不改身份/不丢草稿/不重复业务记录 | PI-07–09 的受控前端/HTTP 场景；持久幂等若采纳须真实 PostgreSQL 并发/重启证据 |
| 任务与成员 | 中间失败仍继续其余账号、群主保留、重入成员不被旧结果误删、未知不重建 | PI-04–06 聚焦浏览器状态 + 既有 R4/R5/R9 对应版本回归；记录 job/群/账号和最后状态 |
| 投递与同步 | 202 不等于 sent，504 与任意中断不同；重复乱序、晚补投、分页并发无重复遗漏 | PI-10/11/18；保留同稳定 ID、clientMsgId、msgId、事件 seq 与时间；历史三秒结果不外推任意规模 |
| Agent/序列 | 前步成功后审计阻塞、未知暂停不重放、失败时间标签、角色不足和限流、接管顺延 | PI-12–17；API 字段与实际页面对照；未知效果不能为了使页面“完成”改成失败 |
| 会话与权限 | REST/WS 同过期、多标签、角色切换、注销、服务故障、viewer 直接请求 | PI-20/21；独立浏览器上下文/会话；验证后台实际拒绝，而不仅是按钮隐藏 |
| 输入与日志 | HTML/长文本/非法变量可控展示、字段错误明确；诊断不带凭据 | PI-03/15/21；使用无敏感真实数据的哨兵样本，核对页面、响应、日志和复制摘要 |

## 5. 待用户评审的少量决定

1. **首批范围：** 是否采纳 PI-07/08、PI-04、PI-12/16、PI-18，以及 PI-09 提示版；是否顺带 PI-14 确认摘要与 PI-03 提交中关闭保护。每项可以单独采纳或暂缓，不必整包批准。
2. **已有群资料细节：** 排序方向；名称是否可清空回退编号；80/500 字符上限。沿用 CR 台账，不重新假定已确认。
3. **输入取舍：** 发送期间锁输入还是保留连续编写；dirty 关闭提醒还是会话草稿；是否需要同字段冲突检测。
4. **恢复与记录范围：** 任务/序列仅同浏览器找回，还是增加轻量持久历史列表；是否本轮增加平台接收层请求幂等。没有充分外部证据的“一键重跑”不推荐。
5. **安全和升级边界：** 多标签统一身份是否本轮支持；viewer 的诊断阅读范围；是否外发日志；是否安排独立备份恢复演练与游标代际机制。真实权限/数据风险一旦复现，应先于效率优化处理。
6. **可选扩展：** C1/C2/C3 是否继续暂缓；只有明确选中才单独估算和验收。
