# 架构评审与演进记录

本系列保存独立架构意见、实施侧复核和阶段变化。它是已有需求与工程约束的另一种审查视角，不是新增的功能需求清单，也不以报告优先级直接授权实现。

## 记录与关联规则

| 类别 | 判断依据 | 记录位置 |
|---|---|---|
| 原始要求的缺口、风险或证据不足 | 原始 A/B 条款、固定协议和验收时限 | 沿用[核心复核](../core-requirements-gap-review.md)中的 CG / V 编号；架构报告引用，不重复建立问题 |
| 已确认的工程质量要求 | [工程要求](../engineering-requirements.md)中的职责、契约、可测试性、可维护性和可观测性 | 本系列保留 AR 编号及最小改进范围；不能全部降为可选新增功能，也不等于批准任意重构 |
| 额外能力与生产部署条件 | 原始要求和已确认质量约束之外的能力、规模目标或运维流程 | 关联[额外增强建议](../product-enhancement-proposal.md)的 PI 编号，维持既有暂缓状态 |

一项发现可以分别关联多类，但应拆清各部分的保证和验收标准。同一触发条件、失败行为和验收标准沿用原编号；相关但不同的风险只建立关联，不强行合并。优先级、源码事实、实验结果、实施授权和人工验收状态分别记录。
