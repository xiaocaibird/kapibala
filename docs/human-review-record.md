# 人工评审与需求调整记录

更新日期：2026-10-02（北京时间）。本记录由负责人要求建立，用于集中查看负责人在需求、评审、验收和交付过程中提出的问题、作出的判断及其实际影响。原有决策、变更、实施和测试记录继续保留；本文是分类索引，不另造一套完成结论。

## 阅读与归属规则

- 区分**负责人主动提出**、**工程侧或审查方提出后由负责人选择**、**负责人实际体验反馈**。批准方案不等于负责人设计了全部实现。
- 每项关联问题、决定、实施结果和证据。没有完成证据的只记待处理或实施中；批准实施、开发自测、QA 判定、人工验收分别记录。
- 同一事项在多个文件中出现时沿用已有编号和来源，不重复计算为多项成果。历史事实不倒写，后续决定注明替代关系。
- 当前对话中的新反馈按语义整理，来源标为“本轮人工验收对话”；没有单独留存的发生时刻、运行版本和正式测试绑定不补造。
- 本文只记实际发生的介入及可核对影响，不推算节省工时、缺陷减少比例，也不把未观察的场景记为人工通过。

## 后续更新方式

新的人工反馈按“发生场景 → 负责人观察/判断 → 处理选择 → 工程实现 → 实测证据 → 验收结论”补录。已存在的 CR、D、CG、PI 或 QA 项直接关联，不重新编号原事项；本表 H 编号只用于索引人工介入。

状态更改需要真实依据。要求确认过但尚未实现的写“已决定/待实施”；实现或自测完成但未获实际验收的保留“待验”；取舍已明确但原保证仍不满足的保留差异或限制。未来提案、源码风险和未经复现的观察不写成已解决缺陷。
