# Agent 与定时序列

## 模块与依赖

`protocol.ts` 定义远端协议、运行时校验、工具描述和结果大小边界。`agent.ts` 编排触发、完整会话、运行互斥、预算和状态收口。`tool-execution.ts` 负责工具校验、审计、权限、发送 key 和副作用恢复，通过显式接口回写步骤和状态。`types.ts` 定义模块内部持久实体。`sequences.ts` 负责变量预检、角色选择、相对排期与进度。`index.ts` 只组合模块与路由。发送统一调用 `MessagingService`，不直接向网关发送消息；移除成员由相同网关适配层处理。

`agent_pending` 对稳定内部消息身份永久去重。群行事务锁与部分唯一索引保护同群最多一个运行；运行期间新消息积累，下次运行一次消费。每个运行的 session advisory lock 跨越远端等待，后台执行不阻塞其他群的 tick。`agent_runs.history` 保存完整协议会话，`agent_steps` 保存原始响应、审计尝试与工具意图。数据库是恢复来源。

## 事务边界

- 账号终态：网关模块在账号状态、成员移除、queued 消息取消的同一事务，把关联 `sequence_steps` 更新为 `skipped` 并填 `sent_at`。调度器后续推进下一步。
- 群不可写：网关模块在同一事务设置运行中序列 `stopped`，设置 Agent 的 `cancel_requested=true`。Agent 当前步结束后完成取消。
- 消息幂等：`agent_send_keys` 与发送入队使用同一事务。重复 key 直接读取当前发送状态，不重复审计。
- 序列启动：所有变量先预检，再锁群行、创建 run 与步骤。无占位符缺失的运行记录能够进入调度。

## 保证与限制

审计无明确 pass 不产生工具副作用；最多尝试三次，结果仍未知则 blocked。明确拒绝不占用发送 key。单次 turn 超时默认 12 秒，活动预算 60 秒、最多 12 步。本进程内等待执行容量的时间在运行接手时补计；活动时间每 500ms 持久化，重启时以新实例启动时刻作为补计下界，停机时间不累计；极端硬终止可能少计最后一个心跳周期。单次执行同时使用本地截止时间，不能因数据库心跳尚未刷新而在预算耗尽后继续审计或发送。

网关没有全局幂等保证。发送入队复用网关模块的保守确认机制。kick 已写入执行意图但没有保存结果就崩溃，以及 Agent 已接收 turn 但本地没有保存响应就崩溃，都缺少能够证明安全重放的协议；运行保留 `running` 与 `recoveryNote`，停止自动重放并发出 inconsistency。该限制不是成功或失败。其余已持久化步骤从断点继续，已入队发送不会重复入队。

数据库 advisory lock 所在连接失效时，运行作用域的取消信号会中止 turn、audit 和嵌套网关调用；旧执行器不能继续落库或执行工具。kick 还接受运行剩余预算信号：若预算在未知外部结果期间耗尽，run 结束为 `failed / wall_clock`，工具意图仍为 `executing`，不把工具副作用记成失败；`recoveryNote` 与步骤说明标明未知结果且不自动重放。运行预算结束与外部副作用是否发生分别记录。

序列按前一步确认发出的观察时刻顺延；调度器持有 session advisory lock，其他实例加入不会重排活跃排期，原调度器退出后新持有者只重排当前最早逾期、尚未入队的步骤。限流不会跳过步骤。所有可查看状态由已提交数据生成。Agent 每实例最多并行四个运行，保留数据库连接池容量给 API、网关与心跳，避免跨远端等待耗尽连接池。

## 验证入口

`tests/integration/automation*.test.ts` 包含独立 PostgreSQL schema 的约束、并发、变量、协议与恢复验证。具体通过结果以测试执行证据为准。

首轮模块验证使用真实 PostgreSQL 与本地 HTTP Agent，发送适配器在测试中替换为写入同一 PostgreSQL 的受控实现。因此这些测试证明本模块的事务、幂等记录和编排行为；真实网关协议与跨模块后果由系统集成测试验证。覆盖：并发启动与预检回滚、双执行器互斥、同 key 复用、协议错误历史、审计阻断与拒绝后重试、待处理消息聚合、自身消息排除、模糊远端结果暂停、最终历史与入队后恢复、kick 策略和未知意图、十二步预算与 8KB 结果上限、关闭 Agent、活动预算到期后丢弃迟到响应、审计期间预算耗尽、序列限流与调度器接管。

实际计时验证通过显式命令执行，默认快速测试跳过这些长等待：

```sh
AUTOMATION_TIMING_TESTS=1 npx tsx --test --test-name-pattern='timing:' tests/integration/automation.test.ts
```

三项分别等待真实的默认 12 秒 turn 超时、3 × 5 秒审计超时、完整 60 秒活动预算。它们与持久化剩余预算的短测试互补，不用缩短配置值替代实际时序。

本轮执行记录：快速集成场景 23 项通过（含实际终止自有 PostgreSQL 后端连接的 turn/audit 回归）；实际计时场景单独执行 3 项通过。turn 与 audit 的测试分别耗时约 13.536 秒、16.463 秒（均包含额外 1.4 秒迟到响应观察），完整活动预算测试约 60.035 秒。kick 预算测试使用遵守取消信号的受控发送适配器，真实网关取消路径仍需跨模块验证。该记录不代表所有网关集成或人工验收已经完成。
