# Agent 与定时序列

## 模块与依赖

`protocol.ts` 定义远端协议、运行时校验、工具描述和结果大小边界。`agent.ts` 编排触发、会话、预算、审计和工具恢复。`sequences.ts` 负责变量预检、角色选择、相对排期与进度。`index.ts` 只组合模块与路由。发送统一调用 `MessagingService`，不直接向网关发送消息；移除成员由相同网关适配层处理。

`agent_pending` 对稳定内部消息身份永久去重。群行事务锁与部分唯一索引保护同群最多一个运行；运行期间新消息积累，下次运行一次消费。每个运行的 session advisory lock 跨越远端等待，后台执行不阻塞其他群的 tick。`agent_runs.history` 保存完整协议会话，`agent_steps` 保存原始响应、审计尝试与工具意图。数据库是恢复来源。

## 事务边界

- 账号终态：网关模块在账号状态、成员移除、queued 消息取消的同一事务，把关联 `sequence_steps` 更新为 `skipped` 并填 `sent_at`。调度器后续推进下一步。
- 群不可写：网关模块在同一事务设置运行中序列 `stopped`，设置 Agent 的 `cancel_requested=true`。Agent 当前步结束后完成取消。
- 消息幂等：`agent_send_keys` 与发送入队使用同一事务。重复 key 直接读取当前发送状态，不重复审计。
- 序列启动：所有变量先预检，再锁群行、创建 run 与步骤。无占位符缺失的运行记录能够进入调度。

## 保证与限制

审计无明确 pass 不产生工具副作用；最多尝试三次，结果仍未知则 blocked。明确拒绝不占用发送 key。单次 turn 超时默认 12 秒，活动预算 60 秒、最多 12 步。活动时间定期持久化，停机时间不累计；极端硬终止可能少计最后一个心跳周期。

网关没有全局幂等保证。发送入队复用网关模块的保守确认机制。kick 已写入执行意图但没有保存结果就崩溃，以及 Agent 已接收 turn 但本地没有保存响应就崩溃，都缺少能够证明安全重放的协议；运行保留 `running` 与 `recoveryNote`，停止自动重放并发出 inconsistency。该限制不是成功或失败。其余已持久化步骤从断点继续，已入队发送不会重复入队。

序列按前一步确认发出的观察时刻顺延；重启只重排当前最早逾期、尚未入队的步骤。限流不会跳过步骤。所有可查看状态由已提交数据生成。

## 验证入口

`tests/integration/automation*.test.ts` 包含独立 PostgreSQL schema 的约束、并发、变量、协议与恢复验证。具体通过结果以测试执行证据为准。
