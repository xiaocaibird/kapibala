## 1. UI-032：职责不变量与可达前提

ADD-ATT-05要求提醒确认不能恢复过期旧游标、改变目录缓存；ADD-DIR-08要求多页相关变化后禁旧分页链，整体刷新成功才替换为新第一页，失败保留旧列表/查询/过期状态。

批准依据同时要求**相关新版本成功呈现后再确认**：提醒提案112、118、122行，实施说明7–9、22、30–33行。没有承诺在多页仍stale、只显示旧结果时提供独立清提示按钮。现UI-032在一次元数据变化之后、没有取得新版本呈现证据就寻找确认入口，联合前提过强。这个判断来自批准契约，未以实现的`!stale`作为产品预期。

另一个前提问题：现用例准备23条，默认20条首页加3条后页，第二页`nextCursor=null`。此时本来就没有可续页资格，不能充分验证“原可用游标因变化被禁止，确认不能重新启用它”。原BLOCKED、原始截图/账本、已签发报告保留；不能据静态分析改PASS，也不要求研发新增按钮或第二份目录缓存。

确认窗口前后可持续被动记录GET/WS/DOM；不允许调用内部attention clear、controller.loadMore或修改页面state。实际公开操作缺失、新版本/范围摘要未呈现、无法关联新请求/响应时记BLOCKED。已观察到错误合并、失败清提示、非法续页或确认修改当前分页数据则FAIL。原UI-032可在新QA修订中拆分这些场景或组织为同一完整用例；修改及执行需另立QA版本和run，不能覆盖原结果。

可选增强联合窗口：若交付者能提供**已有公开路径**，令一个目标新版本已呈现可确认、另一个变化仍使目录stale，则只确认前者并验证stale/旧链禁用保持；后者未呈现提醒应保留。这不是必然可达前提，不为过测增加按钮、双缓存或未经批准行为。

## 3. 严格60秒：删除附加下限，分清实际阶段

原A5.2第258行规定步数及时间**上限**；第164行规定`wall_clock→failed`，没有“必须恰好/至少跑满60秒”的明文。修订前QA在下列位置使用“wall_clock且完整上界<60000即FAIL”，属于添加的原因码解释，不能宣称原文直接要求（位置为起始提交92ddc1d）：

- `tests/support/agent-activity-budget.ts:42–43`；
- `harness/runtime-observation.ts:345–348`；
- `harness/lifecycle-observation.ts:390`；
- `tests/system/capacity-control.spec.ts:423–432`；及对应用例、契约、自测。

本次QA源码修订删除这种仅凭时间较早就自动失败的附加下限，不要求engine精确命中60秒。仍验证合法循环/结束原因、原run一致、failed/wall_clock映射、终止后不再派发或产生副作用；不能用一次毫无依据的立即终止来冒充这些功能要求已满足。任何原因码不真实的失败需给出具体功能/决策证据，不能另造任意最低运行时长。

计时证据须分段：

| 段         | 必须是真实发生的事件                                                     | 用途                                                   |
| ---------- | ------------------------------------------------------------------------ | ------------------------------------------------------ |
| run创建    | 实际创建事务/创建点区间及同run身份                                       | 起点；不拿首个HTTP返回当精确创建                       |
| 活动与接管 | 同epoch实际活动；重启需每epoch/停机段/未保存尾段的完整关联               | 累计活动上限，缺尾段不能拼接持久数                     |
| 停止决定   | 真正取消/停止并阻止继续派发的决定，带实际attempt、进程、时钟域、单调区间 | 判断上限；预设deadline/定时器计划时刻不是实际决定      |
| 终态COMMIT | 同attempt的实际终态事务提交，关联决定且合法先后                          | 持久化/恢复一致性；延迟单独报告                        |
| 公开终态   | QA真实GET/WS读到终态及完整请求响应                                       | 可见性外包络；含提交/轮询/网络，不能直接当活动决定时刻 |

上限判据不加容差：完整真实活动/实际停止决定或新派发下界>60000则FAIL；完整上界≤60000可证明该上限；跨界或缺段时BLOCKED。单epoch的创建至决定差仅在真实活动连续、同run/clockDomain/epoch且没有暂停证据时使用。独立进程在线只提供活动保守上界，不能要求公开running→terminal区间一定与活动/决定区间相交。

CAP-003的公开轮询下界及强制相交判据已在本次源码修订中移出活动裁判。工程`run-terminal.activeElapsedMs`当前来源为`persisted active_ms`及DB样本到终态观察的tail（起始提交`scripts/qa-capacity/runtime.ts:369–393`），没有独立停止决定标记；不能把末端取样区间自动称为完整决定窗口。本次改为同时接入既有capacity控制器与runtime真实activity/lifecycle双流；下一候选需配置这两个入口并提供实际停止决定与同attempt COMMIT配对，仅有capacity入口会具体记录BLOCKED。原容量拒绝、零在途及释放后的零迟发副作用断言保持。

历史e85的三条FAIL及原证据不覆盖。AGENT-025的已保存lifecycle分析已独立证明实际决定下界约60011.182125ms；AGENT-028已保存真实工具等待下界约5000.021625ms，因此本次附加下限复核不消除这些实际超限。CAP-003原`[60004,60071]ms`测试FAIL及持久计量事实保留，但更细的“哪个实际阶段超限”需新决定证据归属；不能把本次静态分析当新候选复测或直接改PASS。

## 4. 5秒工具等待及12步

原2.2第121行既写“最多等5秒”，也写“5秒后仍无法确认→SEND_TIMEOUT”。已确认accepted/sent/failed可以提前返回；**持续未决时提前给SEND_TIMEOUT的下限有条件依据**，不能机械套用60秒删除。

工具计时须关联run、toolUseId、idempotency key、实际executionAttemptId：准备/审计另记；等待段的实际进入、其间每次确认结果、结果准备/交还、history COMMIT和下一turn分别留存。未决支路需证明全等待段没有成功/明确失败，并留实际504接收、查询故障和事件控制。故障开启、504抵达、history提交或下一turn不能重置/替代工具等待起止。原严格5000ms上限保持，无舍入、容差或重复重跑筛掉首次超限。

12步也是上限。第267行明确重复同参数读取的处理由实现决定；特定“无其他合法终止、不同read参数持续推进”夹具可验证步数耗尽及第13次不派发，不能泛化为所有run必须执行12步。

## 5. 跨epoch观测预告的最低核对条件

本契约初次编制时，研发预告了live进程时钟桥接、最近真实采样、外部SIGKILL与退出区间、两epoch关联的方案；当时没有交付固定候选。下面登记所需条件，不改变e85的INT-ACT-001 BLOCKED。QA工具收尾期间已收到固定候选`2716abdd2d43a779b6a0972a6323f895cf2b5b9c`，其接收、适配和实际执行另立记录，不把预告或开发样本直接当QA结果：

1. 每个实际HTTP请求保存外部请求前/完整响应后的单调时钟、实际转发进程的performance.now读数、applicationPid、clockDomain、run/epoch身份、采样区间及账本值。两时钟域通过真实往返形成偏移上下界，不能仅凭时钟都“单调”就直接相减。
2. 区分live-bridge与进程退出后的retained缓存；缓存只能证明最后已知样本，不能作为当前进程时钟校准点。保留每个原始帧与来源，不默认为返回时间就是样本时间。
3. 归属检查完成后才对本轮应用进程强杀。保存SIGKILL实际派发前后、实际exit确认区间、应用/guardian身份。SIGKILL调用返回不等于已经停止；不得按端口杀陌生进程。
4. 旧epoch最后真实活动样本→退出区间和新epoch接管→终止区间分别有上下界；仅有旧安全下界时不能用新epoch账本补成完整量。没有持久化通知不自动等于所有这一段丢失；把实际已提交账本、尚未保存量及无法确定量分开。
5. 数据库/网关/Agent状态保留，新epoch必须接管同run；检查停机排除、进度不倒退、终止后零新增副作用。单进程`includesUnsavedTail=false`保持诚实；外部分析的新完整性声明必须由全部对应原始证据支持。
6. 完整累计活动下界超60000仍FAIL，上界不超才可证上限，跨界/缺失关联仍BLOCKED。不反复采样筛选一条有利路径，不重置环境掩盖恢复，也不追溯补造旧e85尾段。
