# 原始边界用例的裁判收敛

本文件只记录测试设计，不表示产品已执行或通过。五个原 `BLK-SPEC-*` ID 保留追踪身份，`mode` 改为 `automated`，入口为 `tests/system/spec-boundaries.spec.ts`。名称中的历史前缀不决定报告状态。SPEC002 的普通序列失败后是否继续属于尚待产品裁定的业务语义，由单独记录处理。

本轮只读取原始规范、批准决策及 QA 资产。未以业务实现、开发通过记录或产品私有 helper 为 oracle；未运行产品、数据库或浏览器。原始文件 SHA-256 仍为 `c837475ae6b6564bc46c2e6c7f17756e375ec903cf67938a438ef81c18ec9c75`，不覆盖原基线。来源读取基准提交为 `70f988928f2cc5bcda62503e994fc42c43a80872`。

## SPEC001

原文 B1 第 1 条（288 行）先给出 `online` 候选规则，再描述限流不应误作“没有账号”。QA 按生命周期拆成：

- 尚未选定执行者：从 online 的匹配成员中取候选，admin 优于 creator，member 按账号 ID 字典序。admin 限流而 creator 在线、较小 member 限流而较大 member 在线不必向用户另问一个业务规则。
- 已选定、消息已入队后收到 429：遵守 A2（234 行）同账号等待与顺序规则，不能换账号绕过等待，也不能跳过步骤。

脚本覆盖上述两种候选组合及已入队 429 后的同账号 FIFO。手动设置限流只用于构造选择前状态；不因此规定手动限流的恢复期限。实际429场景有明确 `retryAfterSeconds=3`，但此ID不单独声称完成精确到期计时验收。

## SPEC003

原文 156 行明确手动操作是“标记状态”，表边与 CAS 在 208–217 行；只对目标 `disconnected` / `idle` 明确要求调用网关 disconnect。219 行要求推送与已提交状态一致。

脚本验证手动限流、恢复在线、离线、idle 的合法转换、相应 WS 回读、CAS/非法同状态拒绝和离线时无网关发送。下列先前阻塞前提是 QA 过度推导，删除：

- 手动 `online` 必须等价于 `/connect`。
- 无 `retryAfterSeconds` 的手动 `rate_limited` 必须在一个 QA 指定的期限自动恢复。

真实网关 429 的计时恢复继续由原 A1/A2 用例验证。WS拒绝路径只观察记录的300ms，不能把有限观察表述为永远不会再有事件。

## SPEC004

258 行规定连续3次协议错误终止、合法响应清零；259 行的“协议错误”明确包括未知工具和非法入参。它们使用 `tool_use` 错误历史形式，不改变协议错误分类。261 行另明确 `NO_AVAILABLE_ACCOUNT` 不算协议错误。

因此可直接验证：`BAD_JSON → UNKNOWN_TOOL → INVALID_INPUT` 必须3次后结束；两次协议错误之后，一个结构/输入合法但业务上无执行账号的工具调用应清零，之后另两次协议错误仍能到达合法结束。无须用户另定计数规则。

脚本以每次真实 turn 和公开 run 的步骤核对；未被请求的结束响应按 runId 绑定，防止测试夹具把余下脚本误喂给另一次运行。最终导致结束的错误可能没有下一次 turn 可用于观察历史，故以公开步骤核对该最后错误，不能虚构一次只为取历史而发生的 turn。

## SPEC005

260 行要求三次未知审计后 `blocked/audit_blocked`，266 行要求关闭 Agent 后当前步结束再 `cancelled`；原文未规定它们与预算边界的全序优先级。QA 不能因缺少人为排序而把所有重叠场景阻塞，也不能要求某个实现内部分支必定先执行。

脚本在第三次未知审计的响应前停住，确认 run 仍在运行，提交关闭 Agent，再释放响应。两项条件均真实发生，允许与这些条件一致的 `blocked/audit_blocked` 或 `cancelled/cancelled`，共同要求只有当前一步、无下一 turn、无合法审计 pass 时零发送/踢人、活动字段归空、已记录终态在1秒采样窗内稳定。

若在45秒夹具观察窗内尚未建立第三响应屏障，或建立时运行已结束/已过近60秒预算，则先检查已知非法终态、额外turn或未审计副作用，再以具体证据标记该重叠场景BLOCKED；不将夹具等待窗冒充产品审计重试SLA，也不把无法建立窗口假记PASS。

覆盖边界：这是可控重叠，不是物理“同时”；不声称测试60秒预算与取消/审计三者同刻触发。本ID移除 `R-A5-06` 映射，60秒/turn超时由已有 AGENT-024/025 等专项覆盖，三者交错仍属于风险矩阵中的未专门实测组合。没有新设终止耗时SLA，也没有靠放宽副作用要求关闭用例。

## SPEC006

裁判分三层，不能混写为“长度规则都已由用户确认”：

| 层次                        | 依据                                                                 | 本用例的裁判                                                                                                                                                       |
| --------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 原文明确要求                | 120、140、164、265 行                                                | `100000` 截到50；明确ASCII/CJK的500字边界；tool_result有效JSON且不超8192 UTF-8字节、超限标记；rawResponse不超2048字节；结果摘要不超200字                           |
| 本轮保留的版本化资料profile | D024；`docs/group-directory-profile-proposal.md:68`                  | trim；名称1–80且不清空；简介最多500、空白/空串清空为null、PATCH null拒绝；按JavaScript UTF-16长度。将来批准profile改变应更新版本化预期，不把80/500变成永久业务限制 |
| 公开协议自身一致性          | 原文88行要求完整合法input_schema，136、259行要求非法入参按schema处理 | 对0/-1/1.5按本次Agent请求所携schema记录接受/拒绝裁判并检查一致；不固定原文没给出的取整、下限或默认结果算法                                                         |

重要限制：服务端自报schema不能覆盖原文。即使schema自称最大50，原文明确要求`100000`截50仍单独判定；若因此拒绝应FAIL。对emoji工具文本按 code point / UTF-16 / UTF-8分别留 `OBSERVATION_ONLY`，不会把尚无唯一Unicode“字”定义的差异伪称严格通过。D024资料已经明说JS长度，所以其emoji边界可以严格验证，与工具文本观察分开。

脚本覆盖大小限制的普通值与明显超限值，并不声称穷举所有Unicode组合、任意JSON转义膨胀或8191/8192/8193每一种精确封装边界。公开输入schema快照属于本次版本证据，不能替代QA独立业务预期。

## 执行与结论

当前仍为准备期：只允许typecheck、静态用例登记和QA工具自身检查，报告中产品用例保持NOT_RUN。正式执行时由本用例自己的API、网关和Agent账本生成证据；若前置设施不具备应记录具体阻塞，若明确预期被实际反例违反则报告FAIL，不能用“语义待确认”遮盖。

本轮说明收敛的是原有需求的QA解释和版本化契约，不是新增业务范围；也不默认放宽A2/A5的强恢复条款。未覆盖的时间组合、Unicode细分和外部不可判定窗口应继续如实报告。
