[原子条款](catalog.json) 不替换第一轮全局 catalog、candidate 签名、分母、已签报告或原始记录。P0-01 是首轮遗留/回归映射而非新增产品功能；P0-02 将 C1/C2 验收与已有 C3 完整流程复用组合，不重复计同一流程。P1-04 是 D050 批准的新业务政策，其他条款按各自 nature 区分原要求、增强与工程交付证据。73 个条款是追踪单元，不是产品用例数；授权/工程证据与产品行为不得混成通过率。

所有新 case 为 `state: NOT_RUN`。`mode` 区分 automated-driver、manual、existing-regression、real-provider；readiness/dependencies 只表达接入条件，不是执行结果。本文后台未接驱动的场景完整写出人工步骤，automation 不放占位脚本。只有真实操作与断言已经编写并被独立自测的入口才登记自动化。`existing-regression` 也需要绑定新候选重新执行，历史 PASS 不传播。

## 判定和证据

- 明确违反原文/批准条款、且真实前提和因果成立：FAIL。前提未形成、缺最终契约、身份或完整时钟见证：BLOCKED；当前尚未执行仍为 NOT_RUN，而不是提前填 BLOCKED。
- 单项明确 FAIL 优先于随后取证缺口/cleanup异常。复测追加来源，不覆盖首次结果；部分子断言通过不升级整例。
- 不新增产品 SLA、错误码、配置默认值或容差。诊断观察期限是 QA 资源边界；有限时间没看到结果不能证明永久不恢复。原5秒/60秒等仍严格按完整可信区间判定，下界超限 FAIL、跨界不确定 BLOCKED。
- Gateway 实际落地、公开 API/WS/UI、provider 请求/响应及文件字节相互绑定；真实事件确认、事件投递与持久写入时刻不混用。副作用未知保守暂停可以单独证明安全，不构成最终完成。
- 保存 SUT/QA/配置 hash、原文基线、目标资源 owner、run/step/attempt/request/event/msg 等实际可得身份、原始时钟域及请求/事件顺序。不能伪造不存在的标识或拿本机秘密填证据。
- 缺工程 DTO、枚举、保留上限、故障接口或场景前提时引用 [dependencies.json](dependencies.json)，不照当前实现写预期。测试需要稳定窗口但实际协议不支持时明确登记，不用随机等待或直写数据库制造窗口。
