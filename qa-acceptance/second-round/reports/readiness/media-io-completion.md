入口：`harness/media-io-cases.ts#runMediaIoCase(context)`，由统一 runner 使用四份独立环境执行。

- 目录 0500 实际 open EACCES：核真实来源首块与未发完关闭、无目标 FD 残留、无公开半文件路径，恢复权限后核完整真实字节。
- 已打开描述符 write 故障：先在全新的 QA 文件执行 OS 探针。本机自测证实 uchg **不撤销已开 FD 的写能力**，因此不拿这个机制伪造产品写失败，该子项明确 BLOCKED。首次“应拒写”的 QA 自测失败是机制假设不成立，未运行产品；修正后的自测要求准确区分真实拒绝与真实成功并核清理。
- 完整落盘未发布、无引用：真实 PG 发布屏障与 SIGKILL，保持同库同目录后将 MEDIA_MAX_BYTES 收紧为 4；用实际单文件 unlink 拒绝保留删除意图取证，恢复后确认真实 deleted 和文件不存在。
- 同窗口、有真实 running 引用：真实媒体触发与 kick 未知结果暂停形成引用，重启后用独立未引用 control 的实际删除证明 cleanup 已运行；原文件保持至公开取消使原 run 终态，之后确认真实删除。未知 kick 不盲目重发，暂停不计强恢复通过。

所有故障恢复在实际 owned 进程停止后兜底执行；未执行项和清理失败均不算通过。无伪造业务 state，无修改系统时钟，无产品实测结果。
