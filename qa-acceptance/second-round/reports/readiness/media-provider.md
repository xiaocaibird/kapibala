# C1/C2 真实驱动接入检查

本文件记录 QA 驱动建设，不是产品验收结论。所有产品执行结果由根执行器在最终冻结候选上另行生成；本检查未启动 SUT、业务 PostgreSQL 或真实供应方。

已加入独立 HTTP Gemini wire 源、真实请求/响应屏障及外部账本；不导入业务模块、不读取真实 Key、不补幂等。显式计划控制 HTTP 401/429/500、断流、超时、多候选、原生 function call、安全阻断和无效 JSON。原始 usage 类型可保留，服务与上游 ID 不混同。

媒体源作为 owned Gateway 的 HTTP 入口，只有 /media 路径提供 QA 字节/故障，其余公开 Gateway 流量与 SSE 透传。记录真实来源请求不是完整出口观测证明。半流屏障必须再结合实际 .part 文件和持久状态，才声称命中下载崩溃窗口。

媒体生命周期通过 QA 自有进程/数据库管理器接入。只对已完成、确属本例的下载记录调整工程公开的 downloaded_at 年龄字段；不写 ready/deleted/run 状态。完整文件发布前、物理删除后使用目标行事务屏障、实际 PG 等待及文件状态联合取证。引用走真实 Agent trigger/get_recent_messages；未过期和被引用的保留场景增加到期未引用控制附件，实际控制附件删除才能证明清理发生。

修正的测试前提：零天保留不要求瞬间路径稳定可见；旧游标由真实公开分页取得；trigger 在投递附件前启用；未知崩溃子窗口不会阻止后续已接窗口；usage 记录通过独占请求增量及实际 runId/用途关联，不假定 Google 返回服务内部 UUID。

## 首批之后的固定 QA 复测准备

在 `agent/qa-second-round-retest` 上以 QA `87f5aea` 为基线补齐 `SR-C1-004`、`SR-C1-009`、`SR-C1-011` 的接线；本修改没有执行被测系统，没有覆盖首批报告。

- 失败重试：首个真实 503/408/429/断连已结束、已提交 pending/attempts/last_error、真实下一重试时间尚未来临及公开 null 路径联合证明首次等待窗口。独立 HTTP 源仅暂停后续响应，不修改产品时钟或业务行。错过窗口仍记 BLOCKED。
- 崩溃观察：修正稳定文件名为文档约定的 `media-<UUID>.bin`；PG `application_name` 使用短标记，避免被截断后无法匹配。未命中时保留实际 PG/行/文件末态。
- 清路径后恢复：在 ready 提交前已确认完整文件后，将本例唯一附件所在独占目录暂改 0500；产品自己提交 deleting/null，实际 unlink 返回 EACCES/EPERM 且文件尚在。然后硬重启同库同目录、恢复原权限，由产品继续删除。此证据证明“物理 unlink 尚未完成”，包含一次明确的文件系统拒绝；**不声称 unlink 调用从未发出**。
- 错目录实例：用新 owned 进程、同 owned 数据库和新的独占目录实际启动；仅观察到非零退出及文档约定的目录不一致原因才记拒绝。未知启动错误仍为 BLOCKED。

媒体/模型 QA 自测 37 项通过，无失败、无跳过；全 QA TypeScript 检查通过。完整出口观测、引用双向竞争、特定文件 unlink 隔离、旧 schema 完整升级/运行引用生命周期仍未由这些接线取代。

补充接线：`SR-C1-010` 使用本例普通文件的 Darwin `uchg` 标志制造真实单文件 **EPERM**，不将它冒称 EACCES，也不降低整个目录权限。工具自测实际证明：目标 unlink 被 OS 拒绝、另一控制文件能删除、解除标志后目标能删除且字节未改。夹具只接受原 flags 为零、同 uid/inode 的 owned 文件，并在失败路径恢复原 flags。故障在年龄输入之前安装。

`SR-C2-008` 增加相同 session 目录的第二真实离线进程；仅接受其实际非零退出和 `SESSION_DIRECTORY_LOCKED`，同时核对首进程存活及原 owner.lock 字节未变。损坏 JSON、owned 软链、过宽权限三种故障操作真实记录文件，结束后恢复原始字节、inode 和权限。foreign-owner 需要独立 OS 身份，当前不伪造、不提权；该子项 BLOCKED 不会阻止其余变体执行。新增变体后媒体/模型 QA 工具自测 **39 项通过**，无失败、无跳过，TypeScript 通过。仍未在本修正工作中启动产品。

### schema 8 升级尚需接线的具体工作

1. 将固定旧提交 `fb1589df08f00c10e9e62801007b1698d4d0155a` 导出至新的 QA 运行目录，核对 001–008 原 SQL SHA256，独立冻结旧 lock/runtime。不能在现行库里删第九条账本冒充旧库。
2. 分配另一 owned 数据库，用旧标准迁移入口构建 schema8，保存迁移账本、旧数据及归档 hash。
3. 明示构造可得媒体、来源过期媒体、普通历史、running/terminal runs；合成 running 只验证升级的保守引用，不能计真实 Agent 触发。来源必须绑定独立媒体源真实 URL。
4. 候选在该旧库上真实启动并验证明确版本拒绝；其他启动错误为 BLOCKED。
5. 候选标准迁移运行两次，核对原字段/旧账本保持、新 media/reference 投影、完整最终迁移校验。结果行和引用不能由 QA 伪写。
