# C1/C2 真实驱动接入检查

本文件记录 QA 驱动建设，不是产品验收结论。所有产品执行结果由根执行器在最终冻结候选上另行生成；本检查未启动 SUT、业务 PostgreSQL 或真实供应方。

已加入独立 HTTP Gemini wire 源、真实请求/响应屏障及外部账本；不导入业务模块、不读取真实 Key、不补幂等。显式计划控制 HTTP 401/429/500、断流、超时、多候选、原生 function call、安全阻断和无效 JSON。原始 usage 类型可保留，服务与上游 ID 不混同。

媒体源作为 owned Gateway 的 HTTP 入口，只有 /media 路径提供 QA 字节/故障，其余公开 Gateway 流量与 SSE 透传。记录真实来源请求不是完整出口观测证明。半流屏障必须再结合实际 .part 文件和持久状态，才声称命中下载崩溃窗口。

媒体生命周期通过 QA 自有进程/数据库管理器接入。只对已完成、确属本例的下载记录调整工程公开的 downloaded_at 年龄字段；不写 ready/deleted/run 状态。完整文件发布前、物理删除后使用目标行事务屏障、实际 PG 等待及文件状态联合取证。引用走真实 Agent trigger/get_recent_messages；未过期和被引用的保留场景增加到期未引用控制附件，实际控制附件删除才能证明清理发生。

修正的测试前提：零天保留不要求瞬间路径稳定可见；旧游标由真实公开分页取得；trigger 在投递附件前启用；未知崩溃子窗口不会阻止后续已接窗口；usage 记录通过独占请求增量及实际 runId/用途关联，不假定 Google 返回服务内部 UUID。

准备校验：媒体/模型自测 34 项通过，无跳过。其间全目录 typecheck 的并行集成错误曾位于其他线程的 driver-factories.ts 未存在的 Gateway role 方法；由根统一修复和最终校验，不将该时点写成全目录静态通过。自测只使用 QA 自有 HTTP 服务与临时文件，不计产品通过。

正式执行仍需独立冻结 SUT/QA/配置、验证进程/数据库/目录归属，结束后核对实际清理。真实模型及新凭据/费用范围未自动扩大；root 执行器统一记录必要的 BLOCKED 和历史已决定差异。
