## 可重复检查的事实

冻结 target 的 web 命令启动 Vite dev server；候选公开浏览器入口使用 React.StrictMode。失败 trace 显示，导航至序列页产生两个相邻首次 GET（例如 ARC-UI-009 相隔约 1ms），第一个为 `net::ERR_ABORTED`，第二个才返回注入的 429。该 429 尚未到达时第二个请求已经发起，不能把它判为“收到429后无视限流重试”。开发模式挂载→清理→再挂载与该顺序一致；正式生产构建仍需重新验收。

已脱敏摘录 `development-mount-network.json` 只保存 /api/sequences 的时间、状态和取消原因，不复制 trace 中的授权头、cookie 或认证帧。

## 修正与执行边界

主任务已采纳：下一整轮在干净独占 SUT 工作区生成生产 `vite build` 产物并以 `vite preview` 服务，记录构建产物 hash；启动配置和构建由主任务维护。产品源码不改，原永久错误1次/暂时错误最多4次断言不改，不删除任意 aborted 请求，不把所有计数统一+1。本次仅更正运行装配，不能据开发模式首轮断言宣告生产行为违反要求，也不能反向宣告产品已通过。

ARC-UI-001..018 应在生产构建下整组复测；其中上表包含明确假失败或场景污染，其他条目不能因开发模式已有PASS代替新环境的结论。UI-007/008 另已观察到 Agent 桩 TOOLS_INVALID 共因，沿用 Agent schema 修正与独立重测，不改页面断言。
