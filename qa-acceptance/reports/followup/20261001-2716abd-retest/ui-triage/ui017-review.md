# UI-017 首次失败独立只读归因

原始 run `2026-10-01T14-15-16.243Z-aa9bdaa2`、SUT `2716abdd2d43a779b6a0972a6323f895cf2b5b9c`、QA `04e41660aa49b07b1fd8df76e1f3aabfbc21a7f6`。phase 是 developer-preflight，原始结果仍为 **FAIL**。本审核不改冻结用例、原始结果或产品，不新增产品运行。

结论：**目标场景的稳定多页前提未建立，属于 QA 测量前提缺口。** 失败发生于 `console.spec.ts:707` 首次加载更多后期待 23 项，后续改名和注入失败均未执行，不能据此判定“相关变化后的手动刷新失败丢列表”产品缺陷。初始同步阶段用户点击加载更多未保持为 23 项，是本次真实观察，不能被解释成从未发生；其独立产品归责须另核同步中的操作约定，本审核不擅自宣称产品完全正确。

## 需求边界

- `requirements/catalog.json` ADD-DIR-08 → `docs/change-requests.md:94–102`，其中第100行规定活数据分页非快照、单页自动刷新、多页相关变化使整列表过期、禁旧 cursor、刷新成功整体换第一页、失败保留旧列表。
- ADD-ATT-05 → `docs/page-update-notification-implementation.md:5–9` 及 proposal:108–125：目录过期与提醒职责独立，不得靠确认提示恢复旧游标。
- `docs/page-update-notification-implementation.md:30–32` 和 proposal:162 的公开 scope 水位可用于等待实际回放完成，但 marker 本身不是历史事件全部已收的证明。
- 本例只等待 DOM 数量20就分页，没有复用已存在的 `observeDirectory` 水位/完整响应/一个原5秒周期安静前提。这与已修 UI-024/025、UI-028/030 的问题类别相同。

## 最小 QA 纠正方案（本次仅建议，未改源码）

1. 在登录前安装被动 `observeDirectory`；不新增 `goto`、自发 marker、丢弃 WS 帧或调用内部状态。记录真实认证、scope_ready、实收水位事件、连接变化和所有目录请求。
2. 进入实际目录后，等当前单一连接真实回放水位收敛、请求均完成且成功，并经过原 5 秒周期没有相关业务事件/连接边界变化。缺前提或截止期未收敛记 BLOCKED，不把延长随机 sleep 当证据。
3. 保存当前首屏 20 个 ID、精确查询和 nextCursor；基于该 cursor 等真实第二页成功，并核对 3 个身份、23 个唯一 DOM 身份。分页窗口若发生回放、scope变化或首页替换，先保留全部事实，不能把未达到多页场景的 count 失败误归后半段业务。已经明确的 HTTP/协议/身份错误仍优先 FAIL。
4. 只有实际 23 项多页成功呈现后，才执行原改名→过期/禁游标→403故障→保留23→恢复成功换20断言。**原期望、时限、故障类型均不放宽**；用例文字中“刷新503”与当前明确403数据不一致，可仅同步文字。
5. 原 run 首次 FAIL 保留；修正后重新冻结 QA hash，在同一固定候选独立复测。不得用工具修正直接将旧结果改成 PASS。

若修正后稳定前提下仍有 cursor 响应3项而页面拒绝保留23项，应转为独立产品分页/并发读取问题，向研发提供精确 cursor 响应、首页替换时序、WS 水位和相关事件、DOM 身份、SUT/QA摘要。当前已有材料足以复现初始同步重叠，但不足以签发上述目标故障场景的产品缺陷。
