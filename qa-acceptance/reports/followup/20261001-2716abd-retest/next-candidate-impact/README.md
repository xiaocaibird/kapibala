## 既有标准及变更解释

原 A5.2 是从创建起累计真实活动最多 `60000ms`，不是必须用满 60 秒；每轮模型超时配置在 10–15 秒。新策略在剩余活动不足下一轮完整配置超时时结束，可以使 8 秒循环在约 48 秒结束，不能仅凭提前结束判错，也不能钳制账本或凭“决定结束”替代实际终态保存。完整活动/决定/提交包围区间各自保留；下界大于 60000 仍 FAIL，跨界而无更窄证明仍 BLOCKED。没有新增 45 秒、48 秒下限或安全尾差。

首次 kick 的 15 秒来自工程既有 POST 超时，是内部准入策略，不是原文增加整个踢人调用的 15 秒时限。它只能阻止尚未派发的首次 POST；实际 POST 或确认 GET 已开始时，不能用预算不足伪造否定、改写历史或重放副作用。取消按当前步骤完成后生效；没有“必须在释放容量前先 cancelled”或取消优先于所有错误/预算的新增要求。

发送工具持续未决时原文仍要求 5 秒后 SEND_TIMEOUT；已确认成功/失败可提前返回。PG 只读锁等待、取消、ROLLBACK 与返回尾差都不能重置原截止时间。及时已知成功不得仅因清理完成较晚改成 unknown；与此同时实际返回超过严格 5000ms 的时间失败不能被正确状态覆盖。主任务转交的开发锁样本约 `5001–5005ms` 仅提示新版本仍可能 FAIL，不能预先写成 QA 结果。

## 需要补的可区分场景

1. **模型 intent 前后跨门槛。** 配置分别 10000/15000ms（及候选实际配置），从真实创建和活动开始。在真实新 turn intent 前仍足、完成后不足完整配置窗口的同 attempt 窗口内，确认零新模型 POST、原 history/已完成步骤保留且无虚构 TURN_TIMEOUT。完整活动和终态仍服从 60000 上限。现协议没有该阶段受控屏障；普通 8 秒循环仅是其中一个样本。
2. **kick 已派发后预算用尽。** 分开建立真实 POST 已接收、真实 POST 已成功但成员确认未完、真实 504 且确认 GET 在途三种事实；其后预算压力、重启、第二实例都不得重复 POST、把已实际踢出写失败或凭目标再次入群否认旧成功。保守暂停的安全性与原正常续跑义务分开；D039 不是通过豁免。
3. **PG 只读等待 / 清理。** 分别在消息读取、账号必要读取等已确认公开观测阶段持有本次拥有的锁；跨原 5 秒、截止前返回真实 sent、原查询取消/断连、ROLLBACK 失败及清理较晚分别留证。必须确认原查询真实结束及同事务 ROLLBACK 完成才发生下一次查询，不能抛弃 SQL 后另跑后台任务。当前 lifecycle 能关联工具 run/step/toolUse/attempt/key/消息与返回，但没有已交付的 query-attempt/transaction/rollback-complete 控制事件；需工程最小观测契约，不把一般日志或 fixture 私有 effect:none 当否定证明。
4. **零步骤终态。** 需要真实创建后、首次模型派发前的可控窗口，持有期间活动是否累计、窗口归属/TTL/释放须可证明；通过真实 agentEnabled 关闭或真实预算策略形成终态。不能修改 active_ms、run/status/steps 或拦截 API 成功体来造前提。现有 external model 响应屏障已在派发之后，依法可能完成一整步或产生 TURN_TIMEOUT，不保证 zero-step。

可观察到明确定义的重复副作用、状态错误、历史丢失或严格时间下界超限时 FAIL；不能因为旁边缺一段工程见证改成 BLOCKED。缺少真实窗口、身份/起止绑定或区间跨界时才 BLOCKED，保留已完成的独立子断言。普通诊断等待到期不证明永久不恢复。
