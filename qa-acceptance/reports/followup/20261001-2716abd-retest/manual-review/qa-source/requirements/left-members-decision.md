# D042：退群完成后的公开外部成员

<a id="d042"></a>

本记录根据开发交接候选 `993f7588c1105894e0543554209a8c085423589f` 中 `docs/decisions.md` 的 **D042 最终确认**更新验收口径。负责人已在实施侧再次说明公开接口差异后，明确要求“清理平台托管成员、最终留下外部成员”。这属于已确认的公开语义变更；不以实现代码或开发自测结果反推预期，也不修改原始需求文档。

## 原文与已确认差异

- 原始 §2.3 第 158 行要求 leave-all 完成后 `status=left` 且 `members=[]`。
- 原始 B2 第 301–302 行限定退出对象为服务账号，要求群主最后退出，并要求本地与网关成员一致；原始 §2.1 第 54–55 行明确存在外部用户。
- D042 明确：退出托管服务账号、保留外部成员，并在 GET 群详情／列表的公开 `members` 中保留这些外部成员。不移除外部用户、不将群恢复可写、不恢复自动化。
- 因此 QA 不再对**存在外部成员**的 left 群断言公开 `members=[]`。没有外部成员的场景仍必须得到空列表，不能借 D042 放过托管成员残留。原有非群主失败处理、群主最后退出规则保持。

## 可验收断言

`ADD-LEFT-MEMBERS-01` 与 `R-B2-04` 由 `GROUP-010` 关联：对照独立网关实际成员及请求账本，确认托管投影为空、外部 `platformUserId` 与公开详情／列表一致、不重复；所有托管账号恰好一次退出、群主最后退出、无 kick 外部成员。

用例在 leave-all 前创建尚未到期的序列，并让 Agent 停在只读 turn 响应屏障；leave-all 完成后允许当前步骤结束，确认两个运行不再 running、active 指针清空、没有下一轮模型请求或外部发送。完成前后的失败窗口与其余恢复强保证仍由原有用例验收，不用本例替代。SUT 重启时保留数据库和外部桩状态；重启前后都检查新发送／序列被拒绝、外部消息不产生新 Agent run。

`GROUP-006` 保留仅托管成员群的空列表断言；`GROUP-007` 保留非群主失败时的成员及群主保护断言。基础公开契约校验同时检查托管成员的 `platformUserId → accountId` 关系。

## 不凭实现补写的字段语义

D042 没有单独规定外部成员 `accountId` 的 JSON 编码。QA 兼容 `null`、缺省和非托管占位字符串；外部身份不得引用已有托管账号的 ID。`platformUserId` 与原角色枚举仍是必需字段；托管成员的 `accountId` 仍必须精确等于对应服务账号 ID，不因外部兼容而放宽。若需要对某一种外部编码做消费者兼容承诺，应在公开契约中另行登记；这不阻塞外部成员保留这一业务断言。

D042 没有单独约定 left 拒绝写入的精确错误码或停止的新增状态名，当前用例要求结构化 4xx、运行终止、无后续副作用，不把当前实现的某个错误码当作需求。所有已明确原始错误码和状态规则仍由各自原用例检查。

## 准备状态与边界

本次只修改 QA 资产并执行静态／QA 工具校验；`GROUP-010` 产品结果仍为 `NOT_RUN`。1500ms 负向观察是有限取证，15秒终止等待是诊断预算，不能表述为数学证明或新增产品时限。只读 turn 屏障应在最短10秒超时前释放；保持超过9秒视为用例前提不充分，以免把环境耗时引发的 turn timeout 当成退群停止结果。
