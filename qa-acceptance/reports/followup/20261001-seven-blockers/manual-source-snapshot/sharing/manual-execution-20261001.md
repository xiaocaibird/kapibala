# 三项真人验收执行指引

准备版本：QA Git 基点 `fb1589df08f00c10e9e62801007b1698d4d0155a`。本文件仅准备步骤；三项初始均为 **NOT_RUN**。新被测版本、实际 URL、浏览器和执行时间尚未核定，不沿用旧端口，也不改写已有 86ad/a6b 报告。研发提供环境后，QA 核对实际源码/构建/服务身份与资源归属，再登记新一轮执行。

权威用例是 [manual.json](../cases/manual.json)；本文件只是执行展开，不改变断言。来源：原始需求第 4 节群详情的 blocked 醒目提示；[CR-008/009](../../docs/change-requests.md#cr-008-群列表简单搜索与简介摘要) 的目录输入法、搜索与轮询；[CR-011](../../docs/change-requests.md#cr-011-账号操作与群内角色文案) 的账号/角色文案；同文件“CR-006 本次批准与实现”以及 [提醒方案中已选原则](../../docs/page-update-notification-proposal.md)。只采用已批准行为，方案中的旧待评审项和开发自测结果不当验收依据。

## 可立即口述给操作者：MAN-IME-001

**测的是群目录的搜索框，不是聊天输入框或回车发送。** 聊天组合键体验只能另记附加观察。

准备人提供已经 QA 核对的隔离页面并打开群目录；辅助人开始屏幕及网络取证。真人不用查看日志。

1. 切换到平常使用的系统中文输入法，在群目录搜索框逐字拼音输入“测试”。候选框出现后先不要选字，停留一会并切换候选。
2. 选定“测试”，观察搜索框最终文字和结果；再分别试“群资料”和“空 格”，最后一个词中间保留一个空格。
3. 再输入一段拼音，保持候选未确认。辅助人等待一次真实目录轮询，或在另一隔离会话产生约定更新；你继续打字，观察候选、光标、焦点及已有文字有没有被打断。
4. 选定最终中文后，观察结果与最终词一致。辅助人核对组合期间有没有把中间拼音当搜索词请求，并保存时间线。

没有网络取证只能说明“体验已做”，不能证明“没有中间查询”；辅助人稍后给判断，不要求用户理解请求日志。

## 共用准备与记录

| 分工                         | 工作                                                                                                                                                              |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 环境准备人（可为研发/Agent） | 提供真实独占 URL、固定 SUT 完整 SHA/构建摘要、API 与前端绑定、账号、夹具 ID、端口/资源归属及准备日志；只用本轮专属数据。不能只说“main 已更新”。                   |
| QA 辅助人                    | 核对运行对象与批准范围；在操作前登记 run、冻结版本、OS/浏览器/输入法；负责有限网络观察、夹具触发、证据整理和判定。可由 Agent 辅助收集，但不可冒充真人操作或口述。 |
| 真人操作者                   | 实际键盘、系统输入法、浏览器/系统窗口操作；说明看见什么、如何理解。不需要看技术日志。                                                                             |
| QA 复核人                    | 对照原预期核查证据及遗漏；保留首次失败/阻塞，不把重复尝试静默并成一次通过。                                                                                       |

开始前将 [证据模板](../config/manual-evidence-template.json) 另存为 `reports/manual-followup/<session-id>/evidence-package.json`，在同包保存原始真人证据；它不是正式 run，也不创建伪 manifest。填写授权依据、完整 SUT SHA、QA 源文件摘要、实际 URL、前后端构建标识、OS/构建号、浏览器精确版本、视口/缩放、窗口/固定标签/主题及输入法名称/模式。尚未实际核实的字段保持 null，不能用此文档基点当 SUT 版本。新正式 run 尚未建立时 newFormalRunId/startedAt 保持 null，包内状态不自动成为正式验收结果。核心版本或实际页面绑定未确认时先记 BLOCKED，不开始正式判定。

正式记录的 performedAt 必须是该次真人实际完成时间，晚于新 run 开始且不在未来。旧版本练习、口述“应该如此”、历史录屏或自动化 PASS 不填成本轮人工 PASS。每轮记录操作者、辅助人、开始/结束时间及重复原因。

尽量使用普通独立可见浏览器窗口和干净专属配置文件。若浏览器由自动化创建，须核实没有 always-focused 仿真、合成 focus/composition、DOM 修改或其他会改变判据的干预；无法建立真实系统条件则 BLOCKED。只读监听真实请求或输入事件可辅助取证，不得 dispatch 事件、代填文本或赋值 document 状态来替代手工。

浏览器控制扩展也可能改变被观察内容。已有演示现场报告控制扩展会插入 `data-codex-favicon-badge`：焦点／favicon 验收应使用没有这种覆盖的独立普通浏览器，取证不得先 claim 标签而改变图标。保留原生屏幕证据；若发现观察工具改写图标、标题或焦点，记录干预，相关分支重新在无干预环境建立，不能拿工具生成的红点判产品失败。该现场记录尚未绑定版本或正式 run，见[探索性观察](../reports/followup/20261001-seven-blockers/exploratory-observations.json)。

所有录屏只保留 QA 窗口、候选框和必要系统焦点切换；使用合成账号/群名/消息。提前关闭私人聊天、通知预览和无关页面；输入法候选可能含个人词库词，发生时在共享副本遮挡无关内容并说明，不能遮掉关键候选或时间。请求取证仅保留方法、路径、q/order/cursor、状态、开始/结束时刻和必要测试结果 ID；不导出 Cookie、Authorization、密码、完整环境变量。原证据按访问范围留存，脱敏副本标明处理，不涂改关键失败。

## MAN-IME-001：真实系统中文输入法与目录搜索

范围为 ADD-DIR-11。普通 Chromium/Firefox/WebKit 对应的实际浏览器任选已登记目标执行，结果只适用于实际 OS/浏览器/输入法组合；未执行的组合不宣称覆盖。

**准备人：**通过公开界面/API 创建仅本轮的三组可区分目录数据，名称或简介分别含“测试”“群资料”“空 格”，另有不匹配对照。登记真实群 ID 与独立预期匹配表，确认不是仅通过网关 ID 恰好匹配。清除搜索/筛选并回到第一页，等待初始请求完成。网络捕获在操作者输入前开启，覆盖 `/api/group-directory`；不得靠看列表没变化推断没有请求。

**真人与辅助人顺序：**

1. 真人开启记录中的系统中文输入法，以真实物理键盘输入拼音；候选未确认时停留、翻页或改选候选，并口述“候选未确认”。辅助人记 composition 的实际开始/结束时刻或视频对应位置；只读真实事件可佐证，候选框录像不能由模拟事件替代。
2. 真人确认“测试”，辅助人记录确认时刻、随后请求的最终 q、返回匹配 ID 与屏幕显示。对“群资料”“空 格”重复；切换词之前记录上一个已确认条件。
3. 真人再次保持未确认候选。辅助人以日志证实至少一次正常轮询/既有资源刷新真实发生后，真人继续输入并确认。不要让真人点击刷新按钮使输入主动失焦，再误报为产品抢焦点。没有刷新实际发生则该组合前提 BLOCKED，不能凭等待时长认定已发生。
4. 检查组合期间的所有目录请求：允许仍按上一个已确认 q 发出的既有轮询；失败依据是新请求使用未确认拼音/中间候选，或输入被覆盖/焦点被产品抢走。确认后请求应使用最终词，结果对应独立数据表。只记录实际延迟，不自创 debounce 毫秒门槛。
5. 迟到响应组合由辅助人准备，真人仍只操作真实搜索：先确认词 A，证实 A 的真实请求已经在途；辅助人用已登记的本轮网络控制暂留其真实响应；真人确认词 B，让 B 正常完成，再释放 A 原响应。观察最终条件、结果和光标仍属于 B。不得伪造响应数据、合成输入或用旧请求未发出的场景冒称乱序。没有可归属的控制或真实乱序证据则将此子项 BLOCKED，保留前面真实 IME 观察；该条完整人工结论不能预填 PASS。

**证据：**候选操作视频时间段、三个最终词与匹配 ID、每次输入开始/确认、真实轮询时间、q 请求时间线、A/B 原响应次序、光标/焦点观察、异常截图。不能仅凭用户“感觉没有问题”判断网络语义。清空本轮查询、撤销自有响应 hold、关闭本轮窗口；专属群由准备人按资源登记收尾。

## MAN-FOCUS-001：真实系统失焦与标签栏呈现

范围为 ADD-ATT-02/03。本项观察实际标签栏、窗口和跨应用行为；DOM title、favicon 字节或两个自动化 tab 的焦点通过都不替代本项。

**准备人：**优先选“服务账号”页的一个专属账号，从在线到断开构成容易识别的真实更新。页面已成功显示该账号在线并建立当前提醒 scope 后才开始；辅助人登记其 ID、页面路由、当前 scope 建立证据和正常标题/图标。每个分支先确认上一分支并回到干净基线，再用独立的下一次真实变化。辅助人经另一隔离会话的公开 API/界面触发并记录真实状态；不能写页面 DOM、提醒状态或数据库来伪造变化。若改用群消息，必须由另一个会话/外部事件产生新消息，不能使用本标签自身手动发送。

按下表分别完成三轮，每轮保留全过程：

| 真人动作                                                  | 观察与辅助人动作                                                                                                 |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 切到另一个真实标签                                        | 原标签仍在浏览器标签栏可见，辅助人此时产生本 scope 相关变化。记录原标签标题和 favicon 是否出现静态提示。         |
| 用系统应用切换快捷键切到另一个应用                        | 记录前台应用实际改变，再产生新变化。恢复浏览器前后均取包含标签栏的屏幕证据。操作员不在产品页面点击以免顺带确认。 |
| 两个窗口并排，点击另一个应用/窗口，让产品页仍可见但不持焦 | 在页面仍可见时产生新变化；记录窗口失焦和浏览器真实标签栏。不能把 visibility=visible 当 hasFocus=true。           |

每轮继续：

1. 观察提示是否静态稳定，记录标签文字/图标；产品不弹系统通知授权，不播放提醒声音。声音须区分系统输入/切换音与产品音，不能把整机静音当产品无声音的证明。
2. 仅通过标签标题/浏览器工具栏/窗口标题栏恢复焦点，先不点击账号行或新内容。记录提示应保留。若点击内容时顺带发生了相关确认，本次“仅聚焦”前提失效，另开记录重新体验，不能当成功或产品失败。
3. 等相关新状态真实显示，再由真人点击对应账号状态/行中约定的实际确认目标。辅助人先核对这是产品提供的相关操作，不靠内部 clear 函数。记录基础标题/图标恢复，以及其他未确认变化未被本次误清。
4. 补一个失败呈现分支：辅助人通过已登记网络控制让该 scope 的真实快照读取失败，保持原已确认内容；真人失焦后触发相关更新，再只恢复焦点、查看错误/旧内容，提醒仍应保留。恢复读取并成功显示新值后，再做相关操作才清除。若无法建立真实失败窗口，记该子项 BLOCKED，不以正常成功路径替代。

另记录一次已呈现的前台内容正常更新应保持安静。各分支都核对不会请求系统通知权限或播放声音。固定标签、主题、高对比、标签宽度导致标题截断或图标不可辨时记录实际设置：可另用普通宽标签重测，但原组合仍留证，不能只看 DOM 后宣称实际可见。浏览器冻结/休眠时记录事实，不承诺线程停止期间即时显示；恢复后的同步情况与时刻另记，未产生相关事件/未建立 scope 属前提不足。

**证据：**包含真实标签栏的连续屏幕片段、OS 应用/窗口切换、scope 与目标 ID、辅助人触发时间、真实提交/读取结果、首次可见提示、仅聚焦、成功呈现、确认时间。清理时先完成本轮变化确认并记录基础标题恢复，解除本轮网络控制，关闭自有标签/窗口；只清理登记的专属夹具。

## MAN-UX-001：不先教授答案的操作员理解

范围为 R-A6-03、ADD-COPY-01。**这部分由辅助人保管。给操作者只读下面的中性口述任务，不提供判分答案、实现说明或其他用例预期。** 若用户已预读本项 UX 判分答案、产品实现说明或接受过这几个问题的答案讲解，记录资格限制；其反馈仍有价值，但不能冒称本项未经提示的首次理解，需另选符合原前提的真人，否则 BLOCKED。仅看过输入法／焦点操作指引或有普通产品使用经历不自动使其失去资格，按实际接触内容记录。

**准备人：**准备实际公开可读的正常与 blocked Agent 运行，以及 failed、cancelled、unknown 示例（unknown 是消息投递状态，不伪造为 Agent run 状态）；将每个状态绑定其真实资源类型、ID 和公共数据证据。准备具有控制台 admin 登录、群 creator/admin/member 的专属群，以及账号断开/释放说明可见的页面。状态可通过受控外部协议形成，不能改 DOM 假装成产品页面；无法得到某个真实状态则单独登记前提缺项。操作者无需真的释放账号或踢人。

**只向操作者口述：**

1. “请看看这几个群和运行页面，用自己的话说说当前发生了什么，哪些需要你留意；你是从哪里看出来的？”
2. “请看账号页这两个操作，分别说说你觉得它们会做什么，现有账号和历史记录会怎样。可以读页面说明，先不用点击。”
3. “请看登录身份和群成员身份，分别说说你认为它们管什么，以及你从页面哪里得到这个判断。”
4. “还有哪里你看不懂，或者需要问人才能判断？请指出具体位置。”

记录操作者第一反应及原话；可以中性追问“你根据哪里判断”，不能提示“释放不会删历史，对吧”或先解释正确答案。指导后的理解只标“讲解后”，不得覆盖首次误读。

**QA 私有判定依据：**正常阅读能识别 blocked 的显著提示，不仅靠难辨颜色；真实失败/取消/未知状态不能被页面表达成已经成功；控制台管理权限与群内服务账号角色能够区分；断开表示断开网关连接，释放表示回待连接并保留账号及历史。结合截图、实际文字与口述判断明确歧义，不因个人颜色/布局偏好直接判 FAIL。若一个误读无法归因于页面或资格/状态不足，记录问题及不确定性，必要时另找合格操作者复核，不编造通过率门槛。无需要求操作者背出内部枚举、API 或状态机。

**证据：**未经提示的原话/时间、具体页面与截图、对应真实状态、是否中途帮助、先前接触产品的范围、为何认定合格。清理仅关闭本轮页面并收尾专属夹具，保留观察记录。

## 状态、证据导入与收尾

| 状态    | 何时使用                                                                                                            |
| ------- | ------------------------------------------------------------------------------------------------------------------- |
| NOT_RUN | 尚未实际体验；模板保持此值，不伪造 performedAt。不能直接导入人工结果记录器。                                        |
| BLOCKED | 实际版本/环境未核对、真人条件或 UX 资格不满足、故障/乱序前提没建立、关键屏幕/网络证据缺失；指出缺什么及已完成子项。 |
| FAIL    | 前提真实成立且观察到违背明确要求；附具体操作、实际与预期、关联证据。缺证据不能凭猜测记产品 FAIL。                   |
| PASS    | 该项规定步骤和真实前提均完成，必要证据支持全部预期；只适用于已登记环境组合。存在未执行/阻塞子项不得整项 PASS。      |

证据模板是采集表，不是可直接导入的通过结果。先将原始证据与实际时间保存在 `reports/manual-followup/<session-id>/`；`packageRelativePath` 指向包内文件，正式归属尚未确定时 `runRelativePath` 为 null。QA 复核后，从副本为每个实际用例生成一个 [manual-review 格式](../config/manual-review.example.json) 的独立 JSON：caseId、PASS/FAIL/BLOCKED、actual、reviewer、真实 performedAt、非空证据列表。只有符合该新正式 run 的版本与时间边界后，才把证据按原字节归档到 `manual-input/<case-id>/<session-id>/` 并核对摘要，使用该 run 内真实相对路径。不得向旧 86ad/a6b run 补写本轮结果。

新正式 run 已合法建立且版本/范围匹配后才可由 QA 使用：

```sh
npm run record:manual -- --run reports/runs/<new-run-id> --input <completed-review.json>
```

当前 `record:manual` 只接受 phase 为 execution 或 business-acceptance 的正式 run；七项 developer-preflight 不是人工结果录入目标。新的独立人工续测登记入口需由 QA 另行接入，或先建立符合条件的新正式 run 后再执行真人步骤。若体验发生在新 run 开始之前，只保留证据包；不能倒填 performedAt、把准备包改名为正式 run 或伪造 phase 来录入，后续按明确的接收机制处理。

不能拿尚未开始的 run、预演时间、模板空字段或任意 preflight 批次绕过人工录入校验。每例保存首次结果、后续修正/复测关联，明确谁做了真实动作、谁负责技术取证、谁给出结论。结束后辅助人解除自己创建的 hold/故障、恢复专属资源到约定状态、记录精确资源清理；不关闭其他人的窗口或生产/演示服务。
