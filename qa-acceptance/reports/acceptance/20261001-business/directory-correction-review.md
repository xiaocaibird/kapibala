## 已成立的改进与判定边界

- Observer 是被动监听：没有发送 scope marker、改写游标或注入虚构事件。auth 或 scope_ready 单独不会令非零水位通过，必须在当前唯一活动连接实际收到该水位事件；不使用 max(seq) 越过水位的推断。关闭或新连接使旧 epoch 失效。
- 五秒静默期从最后一个相关业务事件、auth、scope 或连接变更起计；待处理目录 GET 必须全部结束，最近一次需要成功正文。单纯 message 保留身份但不重置相关事件边界。UI-024 注入后等待同一 msgId 实际到达，再检查预期周期前的一秒负向窗口，避免把尚未送达当成“不刷新”。
- UI-024 在已建立前提且无新边界时，超过五秒才发起刷新、明确失败状态、请求重叠等仍为断言失败。边界改变导致无法归因于定时器或无关消息时记 BLOCKED 是合理的。该窗口是有限观测，不证明任意调度下的长期周期性。
- UI-025 真实捕获第二页 cursor 请求与完整 JSON，检查20+3条名称、两个响应合并唯一ID=23及末页 nextCursor=null；这证明接口分页数据前提，尚不能代替页面实际身份断言。
- `finally observer.unchanged` 只覆盖可能受合法并发失效影响的数量/轮询等待；后续明确 HTTP 状态、cursor、名称或唯一ID错误不在该包装内，未发现把这些已明确错误统一改成 BLOCKED 的新增逻辑。正文尚未取得与明确 HTTP 非200亦有不同分支。
- 六项工具自测覆盖真实正文异步读取、requestfailed、监听释放、auth/水位/连接边界和有限前提超时。本次只静态核验这些测试，不重复执行；第一项的倒序成功样本需要按上表纠正。

六项原自测扩展为九项，9/9 通过；TypeScript 检查通过。新增纯函数测试包括合法跳号、同连接倒退/重复、换代后独立顺序、公开链接的有序ID及缺失/跨源链接失败。没有运行 SUT、数据库或浏览器；修订后的产品用例仍待统一冻结复测。最终全量 run 的 UI-025 原本为 PASS；本修订是强化其页面身份覆盖，不能与同轮 UI-032 的23/20失败混同。
